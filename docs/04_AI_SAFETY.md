# 실제 AI 연결: 로컬 키·비용 보호와 OpenAI

무료 데모와 실제 OpenAI 연결을 서버 설정으로 선택한다. API 키가 없으면 실제 생성은 차단한다. 유료 호출 검증에는 별도의 실제 키 등록이 필요하다.

사용자가 지식베이스에 등록한 자료는 로컬 서버의 `.eduflow-private/knowledge.sqlite`에 저장된다. AI 모드에서 관련 원문 구간이 검색되면 원고와 함께 OpenAI 생성 요청에 전달된다. 데모 모드는 지식베이스 자료를 전송하지 않는다. 자료 등록·상태 변경은 로컬 화면의 동일 출처 요청만 허용한다. 지식베이스는 자동 갱신되지 않으며 모델이 사용한 출처 ID만 검사한다. 법령·수치와 내부 기준은 원본 및 적용 시점을 사람이 최종 확인해야 한다.

지식베이스 파일 등록은 이 PC에서 Word·한글·PPT를 PDF로 변환하고, PDF 글자를 읽는다. 글자가 불확실하면 로컬 Tesseract.js OCR을 사용한다. OCR 언어 데이터는 처음 사용할 때 외부에서 내려받을 수 있지만 등록 문서의 페이지는 외부 OCR 서비스로 전송하지 않는다. 검토 대기 페이지는 FTS 검색과 AI 보강 대상에서 제외한다. 검토 화면의 변환 PDF와 페이지 이미지 응답은 루프백에서만 제공하고 캐시하지 않는다. 문서 버전·법령의 현재 효력과 OCR의 사실 정확성은 자동 보증하지 않는다.

## 로컬 입력 한도 조정 (2026-10-24)

사용자 요청에 따라 이 PC의 입력 한도를 110,000토큰으로 올렸다. 서버 설정 스키마도 110,000까지 허용하며 그보다 높은 설정은 차단한다. 출력 한도는 8,000토큰, 하루 $1·월 $5·시간당 5회·동시 1회 제한은 유지한다. GPT-5.4 mini 표준 요금 기준 입력 110,000토큰은 $0.0825이고, 출력 8,000토큰까지 포함한 1회 최대 비용은 $0.1185다. 형식 보완 1회를 포함한 최대 예약액 $0.237을 수용하도록 이 PC의 요청당 예산을 $0.24로 조정했다. 캐시 할인은 예산 예약에 반영하지 않는다. 공용 예시 설정의 기본 입력 16,000토큰과 유료 사용 잠금은 유지한다.

## 내 PC에서 사용하는 방법

1. 프로젝트 루트의 `.env.example`을 `.env.local`로 복사한다. 실제 키는 이 파일에만 넣고 채팅·소스 코드·GitHub에 붙이지 않는다. 배포 환경에서는 서버의 비밀 설정을 사용한다.
2. 실제 연결은 `EDUFLOW_GENERATOR=openai`, `EDUFLOW_AI_ENABLED=true`로 선택한다. 모델은 `gpt-5.4-mini-2026-03-17`이고 공식 표준 단가는 입력 0.75달러·출력 4.50달러/100만 토큰이다(2026-10-08 확인). 키 변수는 `EDUFLOW_AI_API_KEY`이며 `NEXT_PUBLIC_`를 붙이지 않는다.
3. 1회·하루·한 달 상한을 USD로 정한다. 예시 상한은 1회 0.10달러·하루 1달러·월 5달러이고 예시 파일의 유료 사용은 `EDUFLOW_AI_ENABLED=false`로 잠겨 있다. 일·월 상한이 없으면 팀 공통 상한을 사용하며, 더 높은 개인 설정은 공통 상한까지 낮춘다. 요금·1회 상한이 없거나 설정이 잘못되면 유료 호출을 막는다. `EDUFLOW_GENERATOR=demo`이면 키와 무관하게 무료 데모다. 설정 오류를 무료 데모 성공으로 숨기지 않는다. 설정 변경 후 서버를 재시작한다.
4. `npm run dev` 또는 `npm start`로 실행하고 `http://127.0.0.1:3000`에서 연다. 두 실행 명령 모두 서버를 이 PC의 루프백 주소에만 바인딩한다. LAN에 공개하거나 터널·프록시·배포 주소로 연결하지 않는다.

`.env.local`과 `.eduflow-private/`는 Git에서 제외된다. 키를 읽는 모듈에는 `server-only`가 있어 브라우저 코드에서 가져오면 빌드가 실패한다. 키는 생성 요청·응답·브라우저 저장·내보내기·사용 장부에 넣지 않는다. 로컬 파일은 계정 권한에 의존하므로 PC 자체의 접근 권한도 관리한다.

## 팀원 공통 한도 (2026-10-11)

각 팀원은 자신의 PC에서 하루 1달러·월 5달러 한도를 따로 사용한다. 공통 정책은 Git에 포함된 `lib/server/ai-config.ts`의 `TEAM_AI_BUDGET_LIMITS`에 있다.

2026-10-31 예외: 운영자가 서버에 넣는 Gemini 팀 키는 무료 등급 사용을 전제로 이 공통 한도에서 제외했다(팀 결정). `geminiConfig`가 `readAIConfig(..., { teamCaps: false })`로 읽고, 대신 Gemini 전용 한도(기본 하루 100달러·월 1,000달러, `EDUFLOW_GEMINI_DAY_BUDGET_USD`·`EDUFLOW_GEMINI_MONTH_BUDGET_USD`)를 비용 장부에 적용한다. 무료 등급에서는 실제 청구가 없지만, 키의 Google 프로젝트에 결제를 연결하면 이 한도까지 청구될 수 있으므로 그 경우 값을 낮춘다. 1회 예산, 입력·출력 토큰 상한, 시간당 요청 수, 동시 1건 제한은 그대로다. OpenAI·Claude 키에는 아래 공통 한도가 계속 적용된다. 서버는 일·월 개인 설정과 공통 정책 중 낮은 금액을 사용하므로 `.env.local`에 높은 값을 넣어도 이 상한을 넘길 수 없다. 공통 정책을 올리려면 소스 변경과 팀 검토가 필요하다.

기존 팀원이 적용할 때는 최신 공통 정책이 반영된 코드를 받은 뒤 `.env.local`의 다음 두 줄만 수정하고 서버를 재시작한다. 기존 파일 전체를 덮어쓰지 않으며 실제 키, 나머지 설정과 비용 장부를 유지한다. 새 팀원은 갱신된 `.env.example`을 복사해 시작한다. 더 낮은 한도를 원하는 팀원은 기존 값을 유지해도 된다.

```dotenv
EDUFLOW_AI_DAY_BUDGET_USD=1.00
EDUFLOW_AI_MONTH_BUDGET_USD=5.00
```

이 방식의 계수 단위는 **팀원 1명이 사용하는 로컬 PC의 프로젝트 폴더**다. 서로 다른 PC의 사용량은 합산하지 않는다. 한 사람이 여러 PC나 별도 프로젝트 복사본을 쓰거나 여러 사람이 한 서버를 함께 쓰면 개인별 한도로 집계되지 않는다. 사용자 계정 기반의 강제 개인 한도는 중앙 인증과 공유 장부를 도입할 때 적용해야 한다. 또한 소스를 수정하거나 앱 밖에서 API를 직접 호출하는 개발자의 사용까지 통제하는 기능은 아니다.

## 비용을 막는 방식

- `mode: ai`인 생성기는 `createGenerateHandler()`에서 자동으로 보호된다. 데모는 키·예산 없이 그대로 사용할 수 있다.
- 허용 모델은 서버 설정의 정확한 모델 이름 하나다. 요청 본문으로 모델·가격·한도를 선택할 수 없다.
- 요청 URL이 루프백 주소이고 브라우저 Origin이 같은 주소일 때만 유료 요청을 받는다. 이는 로컬 테스트의 보조 검사이며 사용자 인증을 대신하지 않는다. 실제 접근 제한은 루프백 바인딩과 함께 적용된다.
- 한 요청에는 최초 생성과 보완 1회를 포함한 **최대 2회분 비용**을 먼저 확보한다. 각 호출의 최대 비용은 `(입력 토큰 상한 × 입력 단가 + 출력 토큰 상한 × 출력 단가) / 1,000,000`이다. 돈은 정수 마이크로달러 단위로 올림 계산한다.
- 1회·일·월 예산을 검사하고, 기본 시간당 5회·동시 1건 제한을 같은 트랜잭션에서 적용한다. 직접 재시도도 새 요청으로 계산한다.
- 정상적으로 한 번만 호출했다면 시작하지 않은 보완 1회분은 돌려준다. 이미 시작한 호출은 성공·오류·취소와 관계없이 최대 비용으로 계속 계산한다. 현재 장부는 실제 청구서가 아니라 보수적인 사용 한도 기록이다.
- 취소 신호를 무시한 제공자 호출은 그 Promise가 종료될 때까지 동시 실행 자리를 유지한다. 화면의 시간 초과만 보고 새 호출을 허용하지 않는다.

한도는 UTC 날짜 기준이다. 한국 기준으로 일 한도는 오전 9시에 바뀐다. 월 한도도 UTC 월 경계를 사용한다. 시간당 제한은 요청 시각에서 직전 60분이다.

## 기록 보존과 장애

`.eduflow-private/ai-budget.sqlite`에 금액·요청 시각·호출 횟수·진행 상태만 저장한다. 원고·결과·키는 저장하지 않는다. Node.js 22.13 이상에 포함된 SQLite를 사용하며, 별도 DB 서비스는 필요 없다. 하나의 PC에서 같은 장부를 사용하는 여러 서버 프로세스의 경쟁 요청도 트랜잭션으로 막는다.

서버를 재시작해도 비용 기록과 진행 중 예약은 유지한다. 기록이 손상되거나 쓰기에 실패하면 유료 호출을 차단하며 새 장부로 자동 초기화하지 않는다. 초기화 표시 파일 `ledger-created`가 남아 있는데 장부가 삭제되거나 내부 표가 없어져도 차단한다. 서버가 강제 종료되면 예약이 남아 호출이 막힐 수 있다. 이때 서버와 제공자 요청이 종료되었는지 확인한 뒤 기록을 검토해야 한다. 비용 한도를 초기화하려고 장부나 초기화 표시를 삭제하지 않는다.

이 장부는 **단일 PC의 지속되는 로컬 디스크용**이다. 서버리스·여러 호스트·팀 공개 배포 전에는 공유 저장소와 사용자 인증으로 바꿔야 한다.

## OpenAI에서 적용한 보호

- 서버 전용 공식 SDK를 사용하며 모델을 고정한다. 설정 단가가 공식 단가보다 낮으면 연결을 막는다. 가격 변경 시 공식 요금을 다시 확인해야 한다.
- `responses.inputTokens.count`로 응답 스키마·지시·원고·설정·보완 자료를 포함한 전체 입력을 계산한다. 토큰 계산에도 원고를 OpenAI에 전송한다. 계산 전 비용과 동시 실행 자리를 예약하고, 취소 후 계산이 늦게 끝나더라도 생성하지 않는다. 계산의 오류·분량 초과에는 생성 비용을 장부에 기록하지 않는다.
- 기본 입력 상한 16,000·출력 상한 8,000토큰에서 생성 1회 최대 0.048달러, 보완 포함 최대 0.096달러를 예약한다. 캐시 할인은 계산에 반영하지 않는다. 이는 모델 생성 비용 상한이며 실제 청구서는 OpenAI 계정에서 확인한다.
- 추론 `none`, `max_output_tokens`, 표준 서비스 등급, 도구 없음으로 요청하고 SDK 자동 재시도는 0이다. 외부 주소 설정값으로 키가 다른 서버에 전송되지 않도록 API 주소도 고정한다.
- 생성과 보완 전체를 합친 시간 제한은 90초다. 브라우저는 95초까지 기다린다. 신호는 계산·생성 요청 모두에 전달한다. 이미 시작한 호출은 취소해도 과금될 수 있다.
- `store:false`를 사용한다. 이것이 OpenAI의 모든 데이터 보관을 없애는 설정은 아니다. [OpenAI 데이터 정책](https://developers.openai.com/api/docs/guides/your-data)을 따른다.
- 엄격한 JSON 출력 후 서버가 필수 항목·장면 수·원문 인용을 재검사한다. 거절·출력 잘림·키/결제 오류에는 자동 재호출하지 않으며 기존 작업을 유지한다.

PDF 페이지 선택과 로컬 미리보기에는 외부 AI 호출이 없다. 생성 시 단순 텍스트 페이지는 원본 번호와 추출 원문으로 보내고, 표·그림·스캔·복잡한 배치·추출 불확실 페이지는 호환 PDF 하나를 base64 `input_file`로 전송한다. 전체 페이지로 유지하는 시각 자료는 최대 1536×2048픽셀과 `detail: high`를 유지한다. 구조를 확인한 표 페이지는 원문·병합 셀·그림 연결, 전체 배치 축소 이미지와 고화질 영역 이미지를 `input_image`로 전달한다. 추출이 불확실한 페이지는 전체 페이지 PDF로 유지한다. 분리 이미지와 PDF 합계는 50MB 미만이고 분리 이미지 상한은 400개이다. 텍스트 전용 자료는 PDF 첨부가 없다. 입력 토큰 계산과 실제 생성에는 동일한 준비 결과를 사용하며 서버 설정의 입력 토큰 상한을 넘으면 생성 전 차단한다. 장면 재생성에서 기존 출처만 참고하도록 선택한 경우 해당 페이지로 먼저 줄이고, 출처를 확인할 수 없거나 전체 참고를 선택하면 현재 선택 범위를 유지한다. 선택 PDF와 호환 PDF 각각의 50MB 미만 검사, 호환 PDF 준비 중 원본 PDF·페이지 이미지 합산 50MB 미만 검사는 토큰·비용 한도와 별도의 검사다. 원본과 브라우저 선택본은 유지한다. 파일은 서버 디스크나 OpenAI Files 저장소에 업로드하지 않으며 선택본의 브라우저 저장은 IndexedDB를 사용한다. 비용 장부의 보수적인 최대 사용량 예약은 그대로이며 실제 청구액으로 표시해서는 안 된다.

## 완료 확인

자동 테스트는 기본 잠금, 누락 설정, 로컬 접근 검사, 1회·일·월 한도, 시간당·동시 실행 제한, 재시작 보존, 서로 다른 프로세스의 경쟁, 손상 장부 차단, 취소 후 예약 보존, 키 없는 데모 동작을 검증한다. 가짜 네트워크 응답을 공식 SDK에 연결해 실제 요청 옵션, 토큰 계산 실패, 거절, 출력 잘림, 재시도 횟수, 보완 자료와 취소를 검사한다. 실제 키로 생성에 성공했는지와 교육 초안 품질은 별도로 검증해야 한다.

## 실제 계정 연결 확인 (2026-10-08)

키 값을 출력하지 않고 등록을 확인했다. 실제 OpenAI 입력 토큰 계산은 성공했지만 생성 API는 HTTP 429와 `type=insufficient_quota`를 반환했다. 실제 초안 생성 성공은 미확인 상태이며, 계정의 결제 잔액·사용 한도를 확인한 뒤 재검증해야 한다. 키·원고가 포함될 수 있는 제공자 원본 오류는 출력하지 않았다.

이 검증에서 Next.js가 루프백 URL을 localhost로 정규화하여 정상 Origin을 거절하는 문제를 수정했다. 브라우저 Host를 검사하되 루프백 주소·포트·Origin의 일치를 강제하고 forwarded 헤더는 사용하지 않는다. `insufficient_quota`가 code가 아닌 type에 들어오는 응답도 결제 오류로 분류하여 재시도 버튼을 표시하지 않는다. 실패한 제공자 요청은 장부 정책에 따라 최대 비용으로 기록하며 실제 청구액을 의미하지 않는다.

## 결제 설정 후 실제 생성 확인 (2026-10-09)

로컬 앱의 `POST /api/generate`를 통해 샘플 탄소중립 원고를 GPT-5.4 mini로 생성했다. 1분·3장면 요청이 약 7초에 성공했고 보완 호출 없이 최초 응답 한 번으로 필수 구조를 통과했다. 브라우저 저장 형식으로 직렬화·복구하고 Markdown·CSV를 생성했다. 기존 브라우저 저장 데이터는 변경하지 않았다. 테스트 결과는 Git 제외 폴더 `.eduflow-private/ai-smoke-result.{json,md,csv}`에 보관한다.

세 장면 모두 AI가 여러 원문 인용과 식별자를 한 필드에 묶어 반환해 단일 구간을 확인하는 근거 검사에서 경고가 표시됐다. 인용을 서버가 검증한 것으로 오인하지 않도록 기존 검토 필요 표시를 유지한다. 원문 근거 형식·품질 개선과 실제 브라우저에서 장면 재생성·편집·저장·내보내기를 이어서 검증해야 한다.

이번 요청의 장부에는 보수적 상한 0.048달러가 기록됐다. 실제 청구액을 뜻하지 않으며 계정 청구는 OpenAI에서 확인한다. 하루 0.5달러·월 2달러 한도는 변경하지 않았다.

## 선택 PDF의 시각 해석 확인 (2026-10-10)

3페이지 중 그림만 있는 2페이지를 선택하여 실제 GPT-5.4 mini로 검증했다. PDF 파일만 전달하는 초기 방식은 그림의 구체적인 내용을 답변에 반영하지 못했다. 선택본과 각 페이지 이미지를 함께 전송하도록 보완한 뒤 파란 사각형·주황색 원·검은 가로선과 좌우 위치를 인식하고 `pdf-page:2` 근거를 반환했다. 다른 페이지는 전송하지 않았다. 기존 비용 장부와 토큰·금액 상한은 유지했다.

별도 로컬 브라우저 화면에서도 업로드 후 자동 페이지 선택, 그림 미리보기, 잘못된 번호 차단, 선택본의 IndexedDB 복구, 새로고침 후 실제 생성 성공을 확인했다. 이는 테스트 도형에 대한 확인이며 산업안전 원고의 사실성·대상별 설명 품질 전체 평가를 대신하지 않는다. 생성 장면의 원본 대조·검토 필요 표시는 유지한다.

## 선택 PDF 하나로 전송 정리 (2026-10-10)

위 PDF·페이지 이미지 동시 첨부 방식은 중복 입력을 줄이기 위해 교체했다. 현재는 선택 페이지의 보이는 내용을 고정한 호환 PDF 하나만 첨부하며 별도의 `input_image`는 보내지 않는다. 변환 없이 PDF만 보낸 시험에서 벡터 도형을 누락하고 다른 페이지 그림을 잘못 인용하는 현상이 재현되어 호환본을 사용한다. 원본과 브라우저 선택본은 그대로 유지하고 전송용 복사본에서만 텍스트·벡터 속성이 페이지 이미지로 바뀐다. 계산·최초 생성·보완에 같은 호환 PDF 바이트를 재사용한다.

18페이지 시험 PDF에서 원본 2~17페이지(16장)를 선택해 실제 생성 검증을 통과했다. 원본 2페이지의 파란 사각형·주황 원·위치·가로선, 9페이지 표의 A17=37·B26=84, 17페이지의 초록 사각형·회색 원·보고서 코드 RPT-6924를 읽고 각각 정확한 원본 페이지를 근거로 반환했다. 입력 계산과 생성에서 PDF 1개·개별 이미지 0개·동일 파일 바이트·16페이지를 검사했다. 최초 생성 1회가 13.344초에 완료됐고 입력 46,302·출력 929토큰을 사용했다. 첫 호환본 시험의 표 확인 실패는 시험 파일의 검정 배경 위 검정 글자 때문이었으며, 흰색 배경으로 수정 후 화면 대조와 재검증을 마쳤다.

현재 로컬 설정은 입력 64,000·출력 8,000토큰, 요청 $0.20·하루 $1·월 $5다. 기존 시간당 5회 제한을 기다린 뒤 검증했으며 비용 장부나 한도는 변경하지 않았다. 생성 1회 최대 $0.084, 보완 포함 최대 $0.168을 예약한다. 시험 결과는 사용자의 실제 PDF 토큰 수를 뜻하지 않으며, 작은 글자·복잡한 표·한국어 원고의 정확성은 실제 자료로 추가 확인해야 한다. 자동 테스트 56개·타입 검사·프로덕션 빌드도 통과했다.
