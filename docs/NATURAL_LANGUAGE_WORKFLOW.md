# 팀원용 자연어 협업 안내

팀원은 Git 명령어를 외울 필요가 없습니다. **자신의 팀 이름과 맡은 일만 알고 있으면 됩니다.** 나머지는 EduFlow 저장소의 규칙을 읽은 Codex가 처리합니다.

## 처음 한 번

GitHub 초대를 수락한 뒤 Codex에 말합니다.

```text
EduFlow 저장소를 내 컴퓨터에 준비해줘. 나는 A팀이야.
```

`A팀` 부분만 자신의 팀으로 바꿉니다.

## 평소에는 작업 지시와 저장 명령만 사용

### 1. 작업 시작

```text
A팀 작업 시작: AI 연결 기능
```

Codex가 팀의 최신 버전을 받고 개인 작업 공간을 만듭니다.

### 2. 기능 개발

```text
AI 연결 기능을 구현해줘. 기존 기능은 유지하고 작업 후 테스트해줘.
```

이후 수정 요청도 평소처럼 자연어로 이어갑니다.

### 3. 최신 팀 작업 내려받기

```text
@최신
```

Codex가 GitHub의 최신 팀 브랜치를 확인해 현재 개인 작업 브랜치에 반영합니다. 저장하지 않은 작업이 있으면 덮어쓰지 않고 `@개인저장`을 먼저 안내합니다. 충돌이 발생해도 임의로 해결하지 않고 이전 상태로 되돌린 뒤 충돌 파일을 알려줍니다.

`@최신`은 개인 PC만 최신화합니다. GitHub에 업로드하거나 팀 브랜치·`main`을 변경하지 않습니다. 최신화한 개인 작업을 GitHub에도 보관하려면 이어서 `@개인저장`을 사용합니다.

### 4. 작업 중 개인 저장

```text
@개인저장
```

Codex가 현재 작업을 개인 작업 브랜치에 기록하고 GitHub에 올립니다. 팀 브랜치에는 반영하지 않고 검토 요청도 보내지 않으므로, 작업 중간 백업에 사용합니다.

### 5. 작업 완료 후 팀 저장

```text
@팀저장
```

Codex가 개인 저장을 완료하고 타입 검사·테스트·빌드를 실행합니다. 모두 통과하면 해당 팀 브랜치로 검토 요청을 만들고 등록된 같은 팀원을 검토자로 지정합니다. 이 명령은 검토 요청 생성까지 허용하지만 실제 팀 브랜치 병합까지 허용하는 것은 아닙니다.

검사에 실패하면 개인 브랜치에는 안전하게 저장하지만 팀 검토 요청은 만들지 않고 실패 내용을 알려줍니다.

### 6. 요청받은 작업 검토

```text
@검토
```

Codex가 나에게 도착한 검토 요청을 찾고, 현재 개인 작업을 건드리지 않는 별도 공간에서 변경 내용을 실행합니다. 화면 변경은 실제 화면으로, 서버·AI 기능은 샘플 입력과 결과로, 문서·설정은 변경 전·후 내용으로 확인합니다. 타입 검사·테스트·빌드 결과와 위험 요소를 함께 보여줍니다.

`@검토`는 확인만 수행하며 승인하거나 합치지 않습니다. 결과가 `승인 가능`일 때 직접 확인한 뒤 아래처럼 별도로 말합니다.

```text
승인하고 팀 브랜치에 합쳐줘.
```

## 팀장이 사용할 문장

팀 결과 검수:

```text
A팀 결과를 검수해줘. 아직 main에는 합치지 마.
```

검수 후 반영:

```text
검수 결과에 문제가 없으면 main 반영을 진행해줘. 실제 merge 직전에 확인받아.
```

전체 팀 최신화:

```text
새 main을 A팀, B팀, C팀 작업 기준에 반영해줘. 충돌이 있으면 임의로 해결하지 말고 알려줘.
```

## 팀원이 기억할 명령 네 개

1. `@최신`: GitHub의 최신 팀 작업을 내 개인 PC에 반영합니다.
2. `@개인저장`: 내 작업만 GitHub에 백업하고 팀에는 보내지 않습니다.
3. `@팀저장`: 검사 후 같은 팀에 검토 요청을 보냅니다.
4. `@검토`: 요청받은 작업을 별도 공간에서 실행하고 승인 가능 여부를 보여줍니다.

처음 작업을 시작할 때만 자신의 팀과 맡은 일을 말합니다. 이후에는 현재 개인 작업 브랜치를 기준으로 팀을 자동으로 판단합니다. Codex가 충돌이나 검사 실패를 알리면 임의로 진행하지 않고 팀에 공유합니다.

브랜치, Commit, Push, Pull Request 같은 용어와 명령어는 필요할 때 Codex가 대신 처리하고 결과만 설명합니다.
