# Mac 로컬 문서 판독·검색 및 선택형 RAGFlow 연결

## 현재 상태

### 2026-11-01: 사용자 요청으로 검수 기능 제거

- 새 처리 흐름은 로컬 PDF/OCR → 원본 이미지 기반 AI 판독 1회 → 원문·표·그림 저장 및 색인이다. 별도 AI 재대조와 품질 사유를 이용한 재보정 호출은 제거했다.
- 결과는 `processed`로 기록한다. 검증을 통과했다는 `passed`나 판정표를 새로 만들지 않는다. 불확실성은 기록에 보존하지만 수동 승인이나 페이지 처리 차단 조건으로 쓰지 않는다.
- 검수 탭, 예외 검수 화면, 표·셀·연결 승인 버튼 및 해당 API는 제거/종료했다. 처리 현황에는 진행률·한도 대기·실행 오류만 표시한다. 자료 관리의 파일 등록도 자동 대기열로 연결한다.
- 이전에 검수로 보류된 추출 후보는 추가 AI 호출 없이 재사용한다. 원본과 과거 기록은 유지한다. 기존에 명시적으로 제외된 페이지, 시험 자료와 격리 판본을 일괄 활성화하지 않는다.
- 정상 페이지는 모델 생성 1회다. 연결 실패 재시도는 페이지당 최대 3회이며 사용자 요청으로 시간당 제한은 해제했다(`EDUFLOW_AI_REQUESTS_PER_HOUR=0`). 일 비용 한도는 사용자 요청으로 $5로 상향했고, 월 $10 한도와 동시 실행 제한은 유지한다. API 입력 토큰 계산 요청은 별도로 발생한다. 비용 장부는 실제 청구액 대신 보수적 상한을 기록한다.
- 추출 내용이 없는 페이지는 건너뛴다. 잘못된 표 좌표 구조는 표 색인에서 제외하지만 후보와 원본은 유지한다. 기술적 실패는 처리 오류로 표시한다.
- 새 그림은 추출 위치를 저장하며, 의미 연결을 검증 완료로 가장하지 않는다. 인접 페이지 관계에 따른 검색 확장·페이지 기반 시각자료 추천은 이번 변경에 포함되지 않았다.

아래는 변경 전 구현과 시험의 이력이다. 현재 처리 정책은 위 항목을 따른다.


### 2026-11-01 후속 수정: 실제 등록 흐름의 일괄 자동 처리

기존 구현은 별도 시험 탭에만 자동 검사를 연결하여, 사용자의 기존 등록 화면에서는 페이지마다 수동 확인이 계속 필요했다. 이번 수정은 기본 진입 화면을 **자동 처리**로 바꾸고 실제 등록 경로와 연결했다.

- PDF 최대 50개를 함께 선택하면 파일별로 순서대로 업로드하고 문서 전체를 영구 대기열에 등록한다. 실패 파일만 남겨 재등록한다. 출처 링크 없는 파일을 공식 자료로 임의 분류하지 않는다.
- 기존 PDF 전체 또는 선택한 문서의 `이 자료 전체 자동 처리`로 재업로드 없이 처리한다. 원래 페이지 번호와 보관 PDF 페이지 번호를 따로 보존한다. 처리 중 원본은 기존 검색 경로에서도 차단하고 완료 시 통과 페이지를 새 판본으로 활성화한다. 기존 원본·수동 수정 기록은 삭제하지 않는다. 검사 중 원본이 변경되면 덮어쓰지 않고 중지한다.
- 별도 로컬 작업자가 화면과 독립적으로 직렬 처리한다. SQLite 대기열·작업자 임대 잠금으로 중복 실행을 막는다. 브라우저를 닫아도 실행하며, Mac 재시작 후 화면을 열면 남은 작업을 재개한다. OS 자동 시작 서비스는 설치하지 않았다. 비정상 종료 시 최대 10분의 임대 만료 이후 재개된다.
- 최초 보정·검사의 내용상 실패는 실패 사유를 넘겨 한 번 더 자동 보정한다. 두 차례에도 해결되지 않는 항목만 미해결 예외로 집계한다. 예외는 검색에서 제외하며 일괄 승인하지 않는다.
- 시간당·일·월 한도와 다른 AI 작업 점유는 **실행 대기**로 분리하고 예정 시각에 자동 재개한다. 보정 후 재대조가 제한된 경우, 원본 이미지 해시가 같은 저장된 후보에서 이어서 검사한다.
- 페이지당 자동 유료 호출은 보수적으로 최대 4회다. 호출 전 대기·한도 오류는 차감하지 않으며 전송 후 결과가 불확실한 실패는 호출로 센다. 비용 장부가 매 호출 한도를 다시 강제한다. 실행 설정이나 호출 상한 중지는 내용 검수 예외와 구분한다.
- 화면은 `자동 대조 통과 / 처리·재보정 대기 / 실행 대기 / 미해결 예외`를 구분한다. 원본 상세는 필요할 때 열며 페이지별 승인 없이 통과 내용이 저장된다. 기존 목록에도 대기열 상태를 표시한다.

사용자가 등록한 **26년 폭염대비 온열질환 예방을 위한 사업장 대응 지침 53쪽**을 전체 대기열에 넣었다. 작업자는 실행 중이며 기존 시간당 5회 한도로 **2026-11-01 12:31:26 한국시간 이후 재개 예정**이다(관찰 시점의 값이며 다른 AI 사용에 따라 달라질 수 있다). 53쪽 검사가 완료됐다는 뜻은 아니다. 50건을 빠르게 끝내려면 실제 페이지 수와 비용에 맞는 처리량 계획이 필요하다. 사용자 한도는 올리지 않았다.

검증: 50개 문서의 등록 후 대기열→검사→저장, 실패 사유를 이용한 재보정, 제한 후 재개, 중지/재개, 후보 재사용, 기존 판본 교체, 원본 변경 방어, 4회 호출 상한을 테스트했다. 판독 응답은 대역이므로 실제 50개 문서의 정확도 평가가 아니다. 전체 테스트 235개 중 234개 통과·기존 건너뛰기 1개. 아래 최초 시험 결과와 모델 오판 기록은 보존한다.

### 최초 구현과 시험 기록

2026-11-01: 기존 에듀플로우 지식베이스에 `자동 검사` 탭과 별도 보관함을 추가했다. 이 Mac만 사용할 수 있다는 사용자 답변에 따라 기본 실행을 로컬 모드로 바꿨다. PDF.js/pdf-parse와 필요 시 Tesseract로 판독 → OpenAI 원본 이미지 보정 → 구조 규칙 검사 → 별도 OpenAI 호출로 재대조 → 통과한 페이지만 SQLite 원문·벡터 저장소에 반영한다. 실패·불확실·미검사는 검색에 반영하지 않는다.

현재 Mac은 메모리 8GB이며 별도 서버나 컨테이너 런타임이 없다. RAGFlow/MinerU 전체는 실행하지 않았다. 원격 어댑터는 선택 기능으로 남겼다. 기본 로컬 경로는 실제 PDF 판독·유료 이미지 대조·로컬 벡터 생성·저장·검색을 실행했다. **독립 정답에 대한 판독 정확도와 검색 품질은 아직 미측정**이다. 테스트 대역의 성공을 실제 판독 성능으로 표시하지 않는다.

## 실제 시험 결과와 발견한 한계

5개 문서에서 각각 1쪽씩 선택했다. 4쪽의 보정을 실행했고, 이 중 개인보호구 1쪽은 재대조도 실행했다. 나머지 추락방호망 1쪽은 기존 시간당 5회 호출 제한에 걸려 대조를 완료하지 못했다. 일 $2·월 $10 한도와 시간당 제한을 그대로 유지했다. 실제 모델 호출 5회의 장부상 상한 차감은 합계 $0.195이며 실제 청구액 측정값은 아니다.

| 자료 | 실제 실행 결과 |
| --- | --- |
| SIF 가이드 11쪽 | 보정자의 불확실성으로 보류. 줄바꿈·제목만 있는 오른쪽 페이지 등을 이유로 들었으므로 과도한 보류 여부를 별도로 확인해야 함 |
| 지붕재 사고사례 1쪽 | 가려진 업체명·사진 연결의 불확실성으로 보류. 원문 마스킹 자체는 오류가 아니므로 정상 자료 보류 가능성이 있음 |
| 그레이팅 5쪽 | 그림 내부 영문 라벨 누락 및 연결 인용을 한 곳으로 특정할 수 없어 보류 |

| 추락방호망 7쪽 | 로컬 판독 완료. 보정 호출 전 `RATE_LIMITED`로 보류. 호출 가능 시 재검사 필요 |

개인보호구 사례를 계기로 모델 판정과 별도로 **실제 셀 경계가 전혀 없는 가상 열**, **여러 긴 표 셀이 본문에 중복되는 경우**를 차단했다. 실제로 구분된 하위 행이 있는 병합 헤더는 허용하는 테스트도 추가했다. 이전 모델 결과와 저장 이력은 삭제하지 않고 후속 격리 사유를 추가했다. 검색 시 현재 규칙을 다시 적용하며, 사용자가 활성 스위치를 켜도 격리 자료는 반환하지 않는다.

최종적으로 이번 시험 자료 중 운영 검색에 사용할 수 있는 자료는 **0건**이다. 이는 오류 탐지율 100%라는 뜻이 아니다. 같은 모델의 보정·재대조가 같은 문제를 놓친 실제 사례가 확인됐고 정상 내용의 과도한 보류도 관찰됐다. 아직 50건 무인 처리에 대한 신뢰성을 주장할 수 없다. 다음 품질 평가에는 독립 정답, 정상 대조군, 숫자·표·그림 연결을 의도적으로 바꾼 사례가 필요하다. 실제 모델로 이 오류 주입 평가까지 완료한 상태는 아니다.

로컬 모델은 약 145MB 다운로드, 384차원, CPU 두 스레드·직렬 실행이다. 실제 로컬 검색 한 번의 관찰에서 시작 포함 약 1초, 해당 Node 프로세스 약 586MB RSS였으나 부하 시험 결과는 아니다. 실제 질의의 첫 결과가 기대한 표 행과 다르기도 했으므로 검색 순위 품질 역시 별도 평가가 필요하다. 저장·검색 작동 확인과 정답률을 구분한다.

다섯 자료는 모두 `testOnly`로 보관한다. 검사와 원격 저장을 통과하더라도 실제 스토리보드 검색은 차단한다. 로컬 활성 스위치만 바꿔도 이 차단을 해제할 수 없다. 운영용으로 쓰려면 적용 적합성을 확인한 후 일반 검사 자료로 새로 등록해야 한다. 특히 오래된 두 자료는 판독 시험용이다. 공식 출처라는 사실이 최신 법적 효력이나 현장 적용 적합성을 보증하지 않는다. 이번 단계에서는 전체 50건의 자료 선정이나 안전규정 내용의 적합성을 승인하지 않았다.

밀폐공간 가이드 후보 `articleNo=427300&attachNo=241400`는 내려받은 파일이 본문 없는 2쪽 표지여서 제외했다. 교육원 후보 다운로드도 HTTP 400으로 실패했다. 임의 파일로 대신하지 않았다.

원본은 `.eduflow-private/validation-corpus/`에 내려받는다. 다음 명령은 해시·쪽수를 확인한 뒤 검사 보관함에만 추가한다. 기존 검색 자료, API 키, 비용 장부는 수정하지 않는다.

```sh
node --conditions=react-server --import tsx scripts/prepare-validation-corpus.ts
```

## 로컬 모드와 선택형 서버 연결

기본은 `EDUFLOW_KNOWLEDGE_MODE=local`이며 별도 서버 설정은 필요 없다. 기존 OpenAI 연결은 유지한다. 최초 한 번 공식 모델을 내려받는다.

```sh
node --conditions=react-server --import tsx scripts/setup-local-knowledge.ts
```

[Transformers.js](https://github.com/huggingface/transformers.js) 4.3.2와 [다국어 MiniLM ONNX 모델](https://huggingface.co/Xenova/paraphrase-multilingual-MiniLM-L12-v2)의 커밋 `2c4055b12046f11709e9df2c122e59ffbdc2f900`, q8을 고정했다. 앱 실행 중에는 고정된 로컬 파일 경로를 사용하며 외부 모델 접근을 금지한다. 이 방식은 라이브러리의 메타데이터 조회가 `local_files_only`만으로 완전히 차단되지 않는 문제도 피한다. 실제 네트워크가 제한된 환경에서 검색을 확인했다.

SQLite의 원문 검색과 로컬 코사인 유사도 검색을 순위 합산하여 사용한다. 원문·페이지·표·그림 연결은 보존하고 벡터는 추가 색인으로만 쓴다. 긴 구간은 겹치는 작은 구간별로 임베딩한 뒤 정규화한다. 현재는 전수 유사도 계산이므로 50건을 넘는 확장 판단은 총 구간 수·메모리·검색 지연을 측정한 후 한다. 기존 등록 자료를 자동으로 유료 재검사하거나 벡터화하지 않는다.

RAGFlow/ParseFixer를 별도 환경에 준비한 경우에만 아래 선택형 설정을 쓴다.

`.env.local`에 아래 값을 설정하고 개발 서버를 다시 시작한다. 기존 `.env.example`의 사용자 변경은 보존했다.

```dotenv
EDUFLOW_KNOWLEDGE_MODE=ragflow
EDUFLOW_PARSEFIXER_URL=http://127.0.0.1:8765
EDUFLOW_PARSEFIXER_KEY=<서버와 동일한 별도 토큰>
EDUFLOW_RAGFLOW_URL=http://127.0.0.1:9380
EDUFLOW_RAGFLOW_KEY=<RAGFlow API 키>
EDUFLOW_RAGFLOW_DATASET=<에듀플로우 전용 데이터셋 ID>
```

RAGFlow는 [1.0.0-rc3 HTTP API](https://ragflow.io/docs/v1.0.0-rc3/http_api_reference)를 기준으로 구현했다. 출시 후보 버전이며 실제 연결 검증 전 운영용으로 간주하지 않는다. 전용 데이터셋을 만들고 임베딩 모델을 설정해야 한다. 임베딩 비용은 RAGFlow 서버에서 발생하며 에듀플로우의 OpenAI 비용 장부에 포함되지 않는다. 초기 배포에는 서버의 로컬 임베딩 모델을 사용한다. ParseFixer 실행 방법은 `services/parsefixer/README.md`에 있다.

원본 대조는 기존 에듀플로우 OpenAI 연결과 고정 모델을 사용한다. 보정 1회·검증 1회이며 SDK 자동 재시도는 없다. 두 호출 모두 기존 영구 비용 장부, 입력·출력 한도 및 일·월 한도를 적용한다. 원본 페이지 이미지를 외부 모델에 보낸다는 사실과 최대 비용을 화면에 표시한다.

## 저장 및 검색의 차단 조건

- `knowledge-validation.sqlite`에는 원본 전체, 선택 페이지, 초기 판독, ParseFixer 결과, 보정 결과, 재대조 판정, 실패 사유, 모델·이미지 해시 및 시각을 보존한다. FTS나 벡터 색인은 없다.
- 한 페이지 단위로 검사한다. 통과한 페이지는 재실행하지 않으며 보류 페이지 재시도는 새 이력을 추가한다. 반영을 시작한 판본은 변경하지 않는다. 수정본은 새 검사 자료로 등록한다.
- 표 셀 겹침·누락, 중복 ID, 원문에서 특정할 수 없는 그림 인용, 보정자가 기록한 불확실성 또는 여섯 대조 항목 중 하나의 실패가 있으면 전체 페이지를 보류한다. 점수 평균으로 실패를 상쇄하지 않는다.
- 선택한 검색 저장소에 빈 문서를 만들고 검색을 끈 뒤 통과한 구간만 넣는다. 기존 보정 결과를 없애는 재파싱 API는 호출하지 않는다. 로컬에서는 `knowledge-vectors.sqlite`에 구간과 벡터를 저장한다.
- 원격 쓰기 도중 실패하면 로컬 자료도 비활성 상태다. 재시도는 저장한 구간 ID를 재사용한다. 응답 유실 후 생성된 원격 고아 구간은 앱의 허용 목록에 없으므로 검색 결과에서 버린다.
- 에듀플로우 검색과 생성은 같은 검색 함수를 사용한다. 공개 완료 문서 ID로 원격 검색 범위를 제한하고, 구간 ID·문서 ID·본문·현재 페이지 구조 해시를 다시 대조한다. 미승인·변조·삭제·비활성 결과는 버린다. 빈 문서 목록으로 전체 데이터셋 검색을 요청하지 않는다.
- 검증 후 수동으로 내용을 바꾸면 해당 페이지의 기존 검증은 무효가 되어 새 검사 자료로 등록해야 검색에 다시 쓰인다. 사용자 수정 자체와 이전 원본은 지우지 않는다.
- 기존 자료 검색은 로컬 검색을 유지한다. 기존 `자료 등록`은 종전 경로이며 자동 대조를 소급 적용하지 않는다. 신규 안전문서 자동 검증에는 `자동 검사` 보관함을 사용한다.

## 확인한 것과 아직 확인하지 못한 것

최종 확인: 타입 검사와 배포 빌드 성공. 전체 자동 테스트 226개 중 225개 통과, 기존 건너뛰기 1개, 실패 0개. 브라우저에서 420px 및 1058px 너비의 표시와 후속 보류 사유·원본 비교를 확인했다. 이 숫자는 소프트웨어 동작 테스트 결과이며 문서 판독 정확도는 아니다.

자동 테스트는 검사 실패·취소 보류, 보정 이력 보존, 원본 보존, 잘못된 표·연결 차단, 동시 처리 잠금, 부분 공개 방지, 검색 허용 목록, 비활성/삭제/변경/후속 격리 반영, API 인증 조건, 로컬 색인 영속성 및 취소 시 쓰기 방지를 검증한다. 자동 테스트에서 원격 서비스 및 모델 응답은 대역이며, 위의 실제 문서 실행 결과와 구분한다.

고정 커밋의 ParseFixer `verify_table_candidate`도 직접 실행했다. 잘못 닫힌 표 태그는 거부했지만 `<table><tr><td>높이</td><td>999m</td></tr></table>`처럼 형식이 정상인 값은 통과했다. 해당 함수는 원본 이미지를 입력받지 않으므로 수치의 원본 일치를 확인하는 기능이 아니다.

보정과 검증은 서로 다른 호출이지만 같은 모델이므로 같은 오류를 놓칠 수 있다. 현재 페이지 밖의 참조나 이어지는 표를 확정적으로 연결하지 못하면 보류한다. 문서 간 관계 그래프나 자동 법령 최신성 판정은 구현 범위에 포함하지 않았다.

실제 성능 평가에는 독립적으로 검수한 정답이 필요하다. 숫자 변경·단위 누락·표 행 이동·그림 연결 교환·정상 대조군을 구분하고 **오류 탐지율, 잘못된 자동 보정률, 정상 보류율, 최종 잔여 오류율**을 각각 분모와 함께 측정해야 한다. 아직 이 수치는 발표하지 않았으며 50건 자동 운영으로 확대하지 않았다.
