# EduFlow 디자인 가이드

작성일: 2026-09-29. 사용자 첨부 Expo 디자인 분석을 Frame 스토리보드 작업 화면에 맞게 재해석했다. 구현 기준은 `app/globals.css`의 공통 토큰이다.

## 방향

작업자가 원고를 해석하고 장면을 설계·검토하는 능률을 높이는 작업 공간. 작업자가 내용을 직접 판단하고 수정하기 쉽도록, AI 제안과 대조할 근거를 필요한 위치에 둔다. 기존 왼쪽 탐색, 상단 3단계 흐름, 원고·설정의 2열 구성, 장면 목록·편집의 2열 구성을 유지한다. 반복 사용에서는 작업 도구가 먼저 보이도록 40px 높이의 제목·행동 줄을 사용한다. 큰 소개 배너, 장식용 목업, 사이드바와 하단의 홍보 문구는 표시하지 않는다. 초보자 안내는 사용 가이드에서 필요할 때 연다.

주요 행동은 검정 버튼, 보조 행동은 흰 바탕과 테두리로 구분한다. 작업 공간을 차지하던 하늘색 소개 배경은 제거했다. 흰 바탕에서 읽기 어렵던 밝은 회색·보라색 안내 문구는 대비를 높인다. 검토 상태는 색과 함께 아이콘·텍스트를 표시한다.

## 글꼴과 크기

- Inter: 영문·숫자, 400/500/600. 한글은 Apple SD Gothic Neo, Noto Sans KR, 시스템 글꼴 순으로 표시한다.
- JetBrains Mono: 장면 번호, 단계 안내, 근거 식별자 등 짧은 구조 정보.
- 입력·편집 화면 제목 22px(모바일 19px), 섹션 제목 15–18px, 본문 13–16px.
- 주요 제목은 600, 본문 400. 한글 제목은 단어를 유지하고, 긴 사용자 입력은 안전하게 줄바꿈한다.
- 글꼴 파일은 프로젝트에 저장하며 방문 시 외부 글꼴 요청을 하지 않는다. 라이선스는 `public/fonts/*-OFL.txt`에 포함한다.

## 크기와 간격

4px 단위를 사용한다. 입력·버튼 모서리 8px, 카드 12px. 기본 카드 간격 20–24px, 내부 여백 20–24px. 단계 탐색 높이 64px, 화면 제목 줄 40px와 아래 여백 16px. 버튼 높이 40px, 주요 행동과 모바일 기본 입력 44px. 작업 화면에는 참고 문서의 96px 마케팅 섹션 여백보다 압축된 간격을 적용한다.

## 주요 화면

1. 원고 입력: 파일 불러오기와 생성 설정 → 자료 미리보기 → 제작 요청·생성 버튼. 직접 입력과 샘플 원고 버튼은 제공하지 않는다. 파일 선택과 드래그 앤 드롭으로 PDF·PPT·한글·Word·TXT를 불러온다. 업로드 문서는 제작 요청 → 제목·본문 검색 → 원고 확인 → 생성 순서로 사용한다. 실제 AI와 데모의 데이터 전송 안내를 구분한다.
2. 장면 편집: 콘텐츠 제목·내보내기 → 장면 목록 → 선택 장면 편집. 상단의 큰 콘텐츠 요약 카드, 개요 펼치기, 전체 검색 이력 안내는 표시하지 않는다. 기존 요약·학습 목표·검색 기록 데이터는 보존하며 출처 확인은 각 장면의 원문 근거에서 한다. 제목 아래에 목적·예상 시간을 바로 편집하고, 화면 설명·나레이션·자막을 작성한다. 스토리보드 이미지에서 검정 배경의 제목·자막 미리보기를 제공한다. 원문 근거에는 원문 인용과 지식베이스의 텍스트·시각자료 근거를 함께 배치한다. 각 카드는 ‘원문’ 또는 ‘지식베이스’ 배지, 문서명, 페이지·문장 위치, 인용문을 표시하고 카드 오른쪽의 ‘대조하기’로 원본을 확인한다. 같은 지식베이스 근거는 한 번만 표시하고 참고 용도를 함께 적는다. 스토리보드 안내창에는 비용·사용법만 두며 근거를 중복 표시하지 않는다. 시각자료는 표 또는 그림을 한 번만 표시하며 같은 내용을 인용문으로 반복하지 않는다. 참고 이미지·근거·검토 메모는 같은 섹션 간격과 제목 규칙을 사용한다.
3. 내보내기: 파일명과 현재 장면 수를 확인한 뒤 PDF 스토리보드·TXT·전체 복사 중 선택한다. 장면 전체의 검토 상태·필터·집계는 표시하지 않는다.

참고 자료의 마케팅 목업·슬로건은 반복 작업 화면에서 사용하지 않는다. 안내를 접거나 ‘다시 보지 않기’를 설정하는 추가 조작 없이 항상 같은 압축된 작업 화면으로 시작한다. 별도의 랜딩 페이지나 가격표·마케팅 탐색을 추가하지 않는다.

## 반응형·접근성

- 1200px 이하: 사이드바와 패널 여백을 줄인다.
- 1000px 이하: 입력·설정과 장면 목록·편집을 세로로 배치한다. 장면 목록은 가로 스크롤한다.
- 760px 이하: 탐색 메뉴를 접고 메뉴 버튼으로 연다.
- 480px 이하: 설정·편집 필드를 한 열로 정리하고 주요 버튼을 전체 너비로 배치한다.
- 입력은 명확한 레이블, 포커스 테두리, 최소 길이 안내를 제공한다. 단계와 현재 메뉴는 보조 기술에도 현재 상태를 전달한다.
- 애니메이션 감소 설정을 존중한다. 로딩·오류·저장 상태는 텍스트로 확인할 수 있다.

## 데이터 연속성

자막과 나레이션은 미리보기 아래 ‘자막·나레이션’ 탭에서 함께 편집한다. 편집 영역이 640px 이상이면 왼쪽 나레이션과 오른쪽 두 줄 자막을 나란히 비교하고, 그보다 좁으면 나레이션 → 자막 순으로 배치한다. 자막 위치·표시 설정은 자막 입력 아래에 모은다. 자막 표시를 꺼도 텍스트는 보존하고 계속 편집할 수 있다. 기존 장면 데이터와 저장·내보내기 형식은 유지한다.

2026-10-09 고객 대상 조정: 호롱불의 주요 교육대상은 산업현장 근무자, 현장 방문자(일반인·기업 관계자·외부 하청업체), 외국인 근로자다. 새 설정에서 초등·중등을 제외하고 이 다섯 선택지로 교체한다. PRD의 해결하려는 문제 3번인 **학습 대상과 난이도에 따라 콘텐츠를 매번 새로 구성하는 문제**를 기준으로 대상과 설명 난이도를 별도로 반영한다. 이번 변경에서는 난이도 선택지를 유지하며, 대상·난이도 조합에 따른 용어·문장 길이·행동 안내의 품질 평가는 후속 작업으로 남긴다. 외국인 근로자 선택이 출력 언어를 자동으로 바꾸지는 않는다.

브랜드 변경과 무관하게 저장 키 `frame-studio-v1`, Board/Scene 구조, 생성 API 계약을 유지한다. 생성은 기존 원문 발췌 데모이며 실제 AI 연동은 별도 작업이다.

## 지식베이스 기본 화면 간소화 (2026-11-01)

기본 ‘처리 현황’에는 자료 추가, 문서별 처리 진행과 상태만 표시한다. 검수·확인 필요 집계, 수동 확인 탭과 승인 버튼은 사용하지 않는다. 호출 한도 대기는 재개 예정 시각, 실행 오류는 사유를 표시한다. AI는 페이지당 한 번 판독하고 저장하며 재검수하지 않는다. 비용·작동 방식은 정보 버튼, 파일 선택·출처 입력은 자료 추가 대화상자로 옮긴다. 원본·과거 기록은 보존하고 자료 관리에서 원본·표·그림을 읽기 전용으로 볼 수 있다.

## 지식베이스 작업 화면 (2026-10-30)

스토리보드와 같은 공통 토큰·글꼴·왼쪽 탐색을 사용한다. 상단에는 짧은 제목과 주요 행동인 ‘자료 등록’만 둔다. 등록 폼은 별도 대화상자에서 파일/본문 방식을 선택하고, 페이지 범위와 발행 정보는 필요할 때 펼친다.

등록 자료 화면은 ‘자료 목록 → 선택한 자료 상세’로 구성한다. 목록에는 제목, 검색 상태, 확인할 페이지 수만 표시하고 항목 전체를 선택 버튼으로 사용한다. 상세 안의 ‘표·그림 / 판독 확인 / 자료 정보’로 작업을 구분한다. 검토 대기 자료를 선택하면 판독 확인을 먼저 연다. 원본 출처는 자료 정보에, 원본 페이지 비교는 해당 표·검토 페이지 옆에 둔다. 검색 제외와 영구 삭제는 ‘자료 관리’에 모으고 삭제는 결과를 설명하는 확인창을 거친다.

표·그림과 판독 확인은 페이지 선택기와 이전/다음 버튼으로 한 번에 한 페이지씩 표시한다. AI 분석은 해당 페이지에서만 실행하고 버튼에 비용 상한을 표시한다. 무료 구조 재판독은 문제 해결 안내 안에 둔다. 표·그림 미감지 페이지는 기본 목록에서 숨기며 필요하면 포함할 수 있다. 승인·실패·분석 결과는 작업한 상세 영역에 표시한다. 판독 초안은 같은 화면에서 탭이나 자료를 바꾸어도 유지되지만, 새로고침 전 서버에 반영해야 한다.

근거 검색은 별도 작업 탭으로 제공한다. 검색어와 결과 수, 출처 페이지를 표시하고 자료 상세로 연결한다. 1000px 이하에서는 자료 목록을 가로 카드로 배치하고, 자료 선택 시 상세 영역으로 이동해 포커스를 준다. 넓은 표만 자체 영역 안에서 좌우 스크롤되며 페이지 전체는 넘치지 않도록 한다. 760px 이하에서는 데스크톱 사이드바 대신 스토리보드 복귀 링크를 표시한다.


## PDF 스토리보드 출력 (2026-10-31)

### 장면별 스토리보드 이미지

장면 편집의 ‘스토리보드’에서 화면 설명, 원문 근거, 연결된 RAG 발췌로 16:9 제작용 이미지를 생성한다. 공통 그림체와 인물·배경 설정은 문서에 저장하며 장면별 수정 요청은 선택 장면에만 적용한다. 현재 첨부 또는 생성 이미지를 다음 생성의 인물·구도 참고로 보낼 수 있다. 원본 표·그림 추천과 생성 이미지는 별도 영역으로 구분하며, 생성 이미지를 원문 증거로 취급하지 않는다.

사용자는 ‘모델 연결’에서 기존 OpenAI 키 또는 Gemini 팀 키를 통한 유료 이미지 생성을 켠다. 현재 글 생성 방식이 OpenAI이고 해당 키가 있으면 OpenAI 이미지를 사용하며, 그 외에는 Gemini 팀 키, 기존 OpenAI 키 순서로 연결을 선택한다. 텍스트 생성 모델 선택은 바뀌지 않는다. 비용, 임시 예약액, 전송 대상과 사용법은 제목 오른쪽의 작은 정보 버튼으로 연다. 연결 실패와 생성 오류는 작업 화면에 바로 표시한다. 미리보기 아래에 이미지 생성·시각자료·자막·나레이션(통합) 탭을 두고, 공통 생성 버튼은 모든 설정 아래의 일반 작업 줄에 둔다. 이미지 호출은 텍스트 생성과 동일한 영구 비용 장부와 하루 $2·월 $10 상한을 공유하며 자동 재시도하지 않는다. 생성 실패·취소·저장 실패·요청 중 장면 변경 시 기존 이미지를 유지한다. 새 생성 이미지는 검토 필요 상태로 저장한다.

스토리보드 생성 단계는 원문 전체와 지식베이스를 다시 검색하지 않는다. 선택 장면에 이미 연결된 원문 인용과 RAG 발췌를 화면 설명·나레이션과 함께 전달한다. PDF 원본 페이지나 RAG 표·그림의 실제 픽셀은 자동 첨부하지 않으며, 사용자가 선택한 현재 이미지만 인물·구도 참고로 첨부한다. OpenAI 참고 이미지는 비용을 제한하기 위해 최대 512px 썸네일로 보낸다.

이미지 원본은 브라우저 IndexedDB, 생성 모델·시각·입력 근거 기록은 문서 초안에 저장한다. 장면 목록은 저장된 이미지 썸네일을 보여준다. 원문·RAG 근거 또는 공통 설정 변경 후에는 기존 이미지의 재생성을 안내한다. PDF에는 이미지와 ‘AI 생성 스토리보드 (원본 증거 아님)’을 함께 표시한다. PNG 개별 내려받기와 기존 이미지 첨부도 유지한다.
