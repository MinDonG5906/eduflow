# EduFlow 디자인 가이드

작성일: 2026-09-29. 사용자 첨부 Expo 디자인 분석을 Frame 스토리보드 작업 화면에 맞게 재해석했다. 구현 기준은 `app/globals.css`의 공통 토큰이다.

## 방향

작업자가 원고를 해석하고 장면을 설계·검토하는 능률을 높이는 작업 공간. 작업자가 내용을 직접 판단하고 수정하기 쉽도록, AI 제안과 대조할 근거를 필요한 위치에 둔다. 기존 왼쪽 탐색, 상단 3단계 흐름, 원고·설정의 2열 구성, 장면 목록·편집의 2열 구성을 유지한다. 반복 사용에서는 작업 도구가 먼저 보이도록 40px 높이의 제목·행동 줄을 사용한다. 큰 소개 배너, 장식용 목업, 사이드바와 하단의 홍보 문구는 표시하지 않는다. 초보자 안내는 사용 가이드에서 필요할 때 연다.

## 시각 언어

| 역할 | 토큰 | 값 |
| --- | --- | --- |
| 기본 바탕 | `--canvas` | #ffffff |
| 보조 바탕 | `--canvas-soft` | #fafafa |
| 선택 상태·배지 | `--surface` | #f0f0f3 |
| 제목·본문 강조 | `--ink` | #171717 |
| 본문·안내 | `--body` | #60646c |
| 보조 문구 | `--muted` | #74777e |
| 주요 버튼 | `--primary` | #000000 |
| 버튼 상호작용 | `--primary-active` | #1a1a1a |
| 구분선 | `--hairline` | #ededf0 |
| 입력·카드 테두리 | `--hairline-strong` | #dcdee0 |

| 입력·요청 오류 | `--error`, `--error-bg` | #b42318, #fff1f0 |

주요 행동은 검정 버튼, 보조 행동은 흰 바탕과 테두리로 구분한다. 작업 공간을 차지하던 하늘색 소개 배경은 제거했다. 흰 바탕에서 읽기 어렵던 밝은 회색·보라색 안내 문구는 대비를 높인다. 검토 상태는 색과 함께 아이콘·텍스트를 표시한다.

## 글꼴과 크기

- Inter: 영문·숫자, 400/500/600. 한글은 Apple SD Gothic Neo, Noto Sans KR, 시스템 글꼴 순으로 표시한다.
- JetBrains Mono: 장면 번호, 단계 안내, 근거 식별자 등 짧은 구조 정보.
- 입력·편집 화면 제목 22px(모바일 19px), 섹션 제목 15–18px, 본문 13–16px.
- 주요 제목은 600, 본문 400. 한글 제목은 단어를 유지하고, 긴 사용자 입력은 안전하게 줄바꿈한다.
- 글꼴 파일은 프로젝트에 저장하며 방문 시 외부 글꼴 요청을 하지 않는다. 라이선스는 `public/fonts/*-OFL.txt`에 포함한다.

## 크기와 간격

4px 단위를 사용한다. 입력·버튼 모서리 8px, 카드 12px. 기본 카드 간격 20–24px, 내부 여백 20–24px. 단계 탐색 높이 64px, 화면 제목 줄 40px와 아래 여백 16px. 버튼 높이 40px, 주요 행동과 모바일 기본 입력 44px. 작업 화면에는 참고 문서의 96px 마케팅 섹션 여백보다 압축된 간격을 적용한다.

## 주요 화면

1. 원고 입력: 간결한 제목·사용 가이드 → 원고 입력과 생성 설정 → 조건 요약·생성 버튼. 빈 상태에서도 붙여넣기, PDF·Word·TXT 불러오기, 샘플 원고가 명확하게 보인다. 업로드 문서는 제작 요청 → 제목·본문 검색 → 원고 확인 → 생성 순서로 사용한다. 실제 AI와 데모의 데이터 전송 안내를 구분한다.
2. 장면 편집: 콘텐츠 제목·내보내기 → 장면 목록 → 선택 장면 편집. 상단의 큰 콘텐츠 요약 카드, 개요 펼치기, 전체 검색 이력 안내는 표시하지 않는다. 기존 요약·학습 목표·검색 기록 데이터는 보존하며 출처 확인은 각 장면의 원문 근거에서 한다. 제목 아래에 목적·예상 시간을 바로 편집하고, 화면 설명·나레이션·자막을 작성한다. 스토리보드 이미지에서 검정 배경의 제목·자막 미리보기를 제공한다. 원문 근거에는 원문 인용과 지식베이스의 텍스트·시각자료 근거를 함께 배치한다. 각 카드는 ‘원문’ 또는 ‘지식베이스’ 배지, 문서명, 페이지·문장 위치, 인용문을 표시하고 카드 오른쪽의 ‘대조하기’로 원본을 확인한다. 같은 지식베이스 근거는 한 번만 표시하고 참고 용도를 함께 적는다. 스토리보드 안내창에는 비용·사용법만 두며 근거를 중복 표시하지 않는다. 시각자료는 표 또는 그림을 한 번만 표시하며 같은 내용을 인용문으로 반복하지 않는다. 참고 이미지·근거·검토 메모는 같은 섹션 간격과 제목 규칙을 사용한다.
3. 내보내기: 파일명과 현재 장면 수를 확인한 뒤 PDF 스토리보드·Markdown·전체 복사 중 선택한다. 검토 필요 장면 수를 함께 안내한다.

참고 자료의 마케팅 목업·슬로건은 반복 작업 화면에서 사용하지 않는다. 안내를 접거나 ‘다시 보지 않기’를 설정하는 추가 조작 없이 항상 같은 압축된 작업 화면으로 시작한다. 별도의 랜딩 페이지나 가격표·마케팅 탐색을 추가하지 않는다.

## 반응형·접근성

- 1200px 이하: 사이드바와 패널 여백을 줄인다.
- 1000px 이하: 입력·설정과 장면 목록·편집을 세로로 배치한다. 장면 목록은 가로 스크롤한다.
- 760px 이하: 탐색 메뉴를 접고 메뉴 버튼으로 연다.
- 480px 이하: 설정·편집 필드를 한 열로 정리하고 주요 버튼을 전체 너비로 배치한다.
- 입력은 명확한 레이블, 포커스 테두리, 최소 길이 안내를 제공한다. 단계와 현재 메뉴는 보조 기술에도 현재 상태를 전달한다.
- 애니메이션 감소 설정을 존중한다. 로딩·오류·저장 상태는 텍스트로 확인할 수 있다.

## 데이터 연속성

2026-10-09 고객 대상 조정: 호롱불의 주요 교육대상은 산업현장 근무자, 현장 방문자(일반인·기업 관계자·외부 하청업체), 외국인 근로자다. 새 설정에서 초등·중등을 제외하고 이 다섯 선택지로 교체한다. PRD의 해결하려는 문제 3번인 **학습 대상과 난이도에 따라 콘텐츠를 매번 새로 구성하는 문제**를 기준으로 대상과 설명 난이도를 별도로 반영한다. 이번 변경에서는 난이도 선택지를 유지하며, 대상·난이도 조합에 따른 용어·문장 길이·행동 안내의 품질 평가는 후속 작업으로 남긴다. 외국인 근로자 선택이 출력 언어를 자동으로 바꾸지는 않는다.

브랜드 변경과 무관하게 저장 키 `frame-studio-v1`, Board/Scene 구조, 생성 API 계약을 유지한다. 생성은 기존 원문 발췌 데모이며 실제 AI 연동은 별도 작업이다.

## 지식베이스 기본 화면 간소화 (2026-11-01)

기본 ‘처리 현황’에는 자료 추가, 문서별 처리 진행과 상태만 표시한다. 검수·확인 필요 집계, 수동 확인 탭과 승인 버튼은 사용하지 않는다. 호출 한도 대기는 재개 예정 시각, 실행 오류는 사유를 표시한다. AI는 페이지당 한 번 판독하고 저장하며 재검수하지 않는다. 비용·작동 방식은 정보 버튼, 파일 선택·출처 입력은 자료 추가 대화상자로 옮긴다. 원본·과거 기록은 보존하고 자료 관리에서 원본·표·그림을 읽기 전용으로 볼 수 있다.

## 지식베이스 작업 화면 (2026-10-30)

스토리보드와 같은 공통 토큰·글꼴·왼쪽 탐색을 사용한다. 상단에는 짧은 제목과 주요 행동인 ‘자료 등록’만 둔다. 등록 폼은 별도 대화상자에서 파일/본문 방식을 선택하고, 페이지 범위와 발행 정보는 필요할 때 펼친다.

등록 자료 화면은 ‘자료 목록 → 선택한 자료 상세’로 구성한다. 목록에는 제목, 검색 상태, 확인할 페이지 수만 표시하고 항목 전체를 선택 버튼으로 사용한다. 상세 안의 ‘표·그림 / 판독 확인 / 자료 정보’로 작업을 구분한다. 검토 대기 자료를 선택하면 판독 확인을 먼저 연다. 원본 출처는 자료 정보에, 원본 페이지 비교는 해당 표·검토 페이지 옆에 둔다. 검색 제외와 영구 삭제는 ‘자료 관리’에 모으고 삭제는 결과를 설명하는 확인창을 거친다.

표·그림과 판독 확인은 페이지 선택기와 이전/다음 버튼으로 한 번에 한 페이지씩 표시한다. AI 분석은 해당 페이지에서만 실행하고 버튼에 비용 상한을 표시한다. 무료 구조 재판독은 문제 해결 안내 안에 둔다. 표·그림 미감지 페이지는 기본 목록에서 숨기며 필요하면 포함할 수 있다. 승인·실패·분석 결과는 작업한 상세 영역에 표시한다. 판독 초안은 같은 화면에서 탭이나 자료를 바꾸어도 유지되지만, 새로고침 전 서버에 반영해야 한다.

근거 검색은 별도 작업 탭으로 제공한다. 검색어와 결과 수, 출처 페이지를 표시하고 자료 상세로 연결한다. 1000px 이하에서는 자료 목록을 가로 카드로 배치하고, 자료 선택 시 상세 영역으로 이동해 포커스를 준다. 넓은 표만 자체 영역 안에서 좌우 스크롤되며 페이지 전체는 넘치지 않도록 한다. 760px 이하에서는 데스크톱 사이드바 대신 스토리보드 복귀 링크를 표시한다.


## PDF 스토리보드 출력 (2026-10-31)

### 장면별 스토리보드 이미지

장면 편집의 ‘스토리보드’에서 화면 설명, 원문 근거, 연결된 RAG 발췌로 16:9 제작용 이미지를 생성한다. 공통 그림체와 인물·배경 설정은 문서에 저장하며 장면별 수정 요청은 선택 장면에만 적용한다. 현재 첨부 또는 생성 이미지를 다음 생성의 인물·구도 참고로 보낼 수 있다. 원본 표·그림 추천과 생성 이미지는 별도 영역으로 구분하며, 생성 이미지를 원문 증거로 취급하지 않는다.

사용자는 ‘모델 연결’에서 기존 OpenAI 키 또는 Gemini 팀 키를 통한 유료 이미지 생성을 켠다. 현재 글 생성 방식이 OpenAI이고 해당 키가 있으면 OpenAI 이미지를 사용하며, 그 외에는 Gemini 팀 키, 기존 OpenAI 키 순서로 연결을 선택한다. 텍스트 생성 모델 선택은 바뀌지 않는다. 비용, 임시 예약액, 전송 대상과 사용법은 제목 오른쪽의 작은 정보 버튼으로 연다. 연결 실패와 생성 오류는 작업 화면에 바로 표시한다. 미리보기 아래에 자막·나레이션·시각자료·이미지 생성 탭을 두고, 공통 생성 버튼은 모든 설정 아래의 하단 고정 작업 막대에 둔다. 이미지 호출은 텍스트 생성과 동일한 영구 비용 장부와 하루 $2·월 $10 상한을 공유하며 자동 재시도하지 않는다. 생성 실패·취소·저장 실패·요청 중 장면 변경 시 기존 이미지를 유지한다. 새 생성 이미지는 검토 필요 상태로 저장한다.

스토리보드 생성 단계는 원문 전체와 지식베이스를 다시 검색하지 않는다. 선택 장면에 이미 연결된 원문 인용과 RAG 발췌를 화면 설명·나레이션과 함께 전달한다. PDF 원본 페이지나 RAG 표·그림의 실제 픽셀은 자동 첨부하지 않으며, 사용자가 선택한 현재 이미지만 인물·구도 참고로 첨부한다. OpenAI 참고 이미지는 비용을 제한하기 위해 최대 512px 썸네일로 보낸다.

이미지 원본은 브라우저 IndexedDB, 생성 모델·시각·입력 근거 기록은 문서 초안에 저장한다. 장면 목록은 저장된 이미지 썸네일을 보여준다. 원문·RAG 근거 또는 공통 설정 변경 후에는 기존 이미지의 재생성을 안내한다. PDF 이미지 출처에는 ‘AI 생성’과 모델명을 표시한다. PNG 개별 내려받기와 기존 이미지 첨부도 유지한다.

스토리보드는 최종 삽화보다 화면 설명의 인물·시선·동작·카메라 거리와 자료 배치를 우선한다. 흑백 스토리보드는 단순한 선화로 요청하며 기존 OpenAI low 품질을 유지한다. 생성 모델에는 자료 자리의 백분율 좌표만 전달하고 해당 영역을 비우도록 요청한다. 앱은 추천 사진의 실제 원본 크롭과 표의 추출 셀 내용을 해당 위치에 합성한다. 사진을 새로 생성하거나 표의 숫자를 다시 쓰지 않는다. 원본 사진을 찾을 수 없으면 ‘원본 사진 확인 필요’로 표시한다.

추천 자료는 화면 설명을 참고한 초기 배치로 표시한다. 왼쪽·오른쪽·전체·하단 빠른 배치, 드래그·방향키 이동, 오른쪽 아래 모서리의 크기 조절과 표시 해제를 지원한다. 위치·너비·높이의 숫자 입력란은 두지 않고 미리보기에서 직접 조작한다. 수정 위치는 visualPlacements에 저장하며 문서 복원·장면 이동·텍스트 재생성 때 유지한다. 기본 배치는 자막 공간을 남긴다. 제거된 자료의 이미지는 표시하지 않는다. 스토리보드 배경 크기 기능은 제거하고 모든 배경을 화면 비율에 맞춘다. 예전 초안의 scalePercent 값은 읽기 시 제거한다.

장면의 subtitle을 스토리보드에 직접 합성한다. 새 장면·장면 재생성은 서로 다른 자막 두 문장을 줄바꿈으로 생성한다. 자막 탭에서 자막 1·자막 2를 편집하며 기존 초안의 문장은 임의로 재생성하지 않는다. 문장을 자동으로 줄바꿈하고 자료와 덜 겹치는 위·아래 위치를 선택한다. 사용자는 subtitleSettings에서 표시 여부와 위·아래 위치를 지정할 수 있다. 긴 자막은 글자 크기를 줄이고 최대 8줄을 표시하며 생략 여부를 안내한다. 전체 자막은 PDF의 별도 자막 항목에 남는다. 사진·표·자막은 PNG와 PDF에도 같은 배치로 합성하며 편집 손잡이는 출력하지 않는다. 원본 사진 로딩과 합성은 로컬 처리이며 추가 AI 호출이 없다. PDF는 앱의 기존 원본 크롭 로직을 재사용하고 내보내기 동안 같은 사진을 캐시한다.

### PDF 레이아웃

영상 제작용 A4 가로 문서는 왼쪽 참고 이미지·출처·장면 정보, 오른쪽 자막·내레이션·연출 가이드를 유지한다. 웹과 같은 흰 바탕, 중립 회색 본문·구분선, 검토 상태 색상과 텍스트를 사용한다. 웹 전용 사이드바·버튼·반응형 규칙은 인쇄물에 적용하지 않는다.

인쇄 본문은 10pt, 줄 간격은 14pt, 문서 제목은 14pt로 구분하고 로컬 한글 글꼴을 PDF에 포함한다. 장면은 새 페이지에서 시작하며 긴 제목·출처·목적·본문·검토 사유는 생략하지 않고 필요한 만큼 다음 페이지로 이어진다. 가로·세로 이미지는 비율을 유지해 전체가 보이도록 배치하며 이어지는 페이지에도 같은 장면 이미지를 표시한다. 자동 검증 외에 PDF 전체 페이지를 렌더링해 글자·이미지 잘림과 겹침을 확인한다.


## UI 일관성 원칙 (2026-10-31)

이후 모든 UI 작업은 같은 흐름과 조작 규칙을 따른다. 미리보기 → 관련 설정 → 실행 순서로 배치하고 주요 실행 버튼은 설정 이후에도 쉽게 접근할 수 있게 둔다. 표시 여부는 동일한 스위치, 설정 전환은 동일한 탭, 부가 설명은 제목 옆 정보 버튼을 사용한다. 오류와 조치가 필요한 상태는 숨기지 않는다. 반복 설명과 긴 비용 문구를 작업 화면에 늘어놓지 않는다. 입력 높이·간격·포커스·선택 상태를 통일하고 좁은 화면에서도 가로 넘침 없이 사용할 수 있는지 확인한다. 제품 용어는 ‘스토리보드’로 통일한다.

스토리보드 미리보기는 어두운 16:9 작업 영역이다. 배경 이미지가 없는 장면은 제목과 자막을 직접 표시하며 PNG도 같은 제목 카드로 저장한다. PDF는 등록 이미지·원본 참고 페이지가 모두 없을 때 같은 제목 카드를 표시한다. 원본 사진·표 배치와 자막은 PNG·PDF에 유지한다.


장면 편집 상단은 제목과 예상 시간으로 간소화한다. 장면 목적·화면 설명은 바로 아래에서 펼쳐 편집한다. 나레이션은 자막 바로 옆의 전용 탭에서, 시각자료 제안은 시각자료 탭에서 추천 사진·표와 함께 편집한다. 같은 내용을 상단 입력란에 중복 표시하지 않는다. 추천 자료가 없어도 시각자료 제안을 작성할 수 있고, 이동한 필드는 기존 저장·재생성·내보내기 데이터에 그대로 연결된다.


## 편집 화면 보완 (2026-11-02)

- 미리보기 아래 탭은 자막 → 나레이션 → 시각자료 → 이미지 생성 순서로 두고 자막을 기본으로 연다. 핵심 결과물을 먼저 보여주고, 유료 연결이 필요한 이미지 생성은 마지막에 둔다. 마지막으로 연 탭은 같은 브라우저 탭에서 장면을 바꿔도 유지한다(sessionStorage, 저장 실패 시 기본값).
- 이미지 작업 막대와 연결 안내는 탭 영역 안에 둔다. 하단 고정은 탭 영역 안에서만 동작하므로 미리보기와 자막을 가리지 않는다.
- 장면 제목은 줄바꿈되는 입력란을 사용한다. Enter와 붙여넣은 줄바꿈은 공백으로 바꿔 한 줄 제목 데이터를 유지한다.
- 콘텐츠 제목 아래에 생성 조건(대상·난이도·출력 언어)과 총 시간/목표 시간, 검토 완료 수를 한 줄로 표시한다. 목표의 ±15%를 벗어나면 시간 칩을 경고색으로 표시한다.
- 검토가 남은 다른 장면이 있으면 편집 하단에 ‘다음 검토 장면’ 버튼을 둔다. 현재 장면 다음부터 순환하며 찾는다.
- 편집 화면 상단의 ‘장면 편집 | 대본 보기’ 전환으로 전체 장면의 나레이션과 자막(1·2)을 한 화면에서 읽고 고친다. 장면마다 번호·구간·제목·시간·검토 상태를 함께 보이고, 수정은 장면 편집과 같은 경로로 ‘수정됨’에 기록한다. 선택은 같은 브라우저 탭에서 유지한다(sessionStorage).
- 대본 보기는 검토 필터와 무관하게 모든 장면을 보여주며, ‘이 장면 편집’으로 해당 장면을 연 채 장면 편집으로 돌아간다. 장면 한 줄(메타 | 대본)을 재사용 단위로 두어 이후 번역 열을 옆에 붙일 수 있다.
- 화면 높이 720px 이하에서는 입력 화면의 생성 조건 막대를 고정하지 않는다.
- 바닥글, 사이드바의 워크스페이스·프로필·저장 안내, 상단 경로 표시, 원고 작성 팁, 반복되는 지원 형식·검토 권유 문구처럼 조작에 쓰이지 않는 문구를 제거했다. 오류·저장 차단·외부 전송 안내처럼 판단에 필요한 문구만 남긴다.
- 대본 보기에서 ‘시청자 언어’를 고르면 장면마다 한국어 원본(읽기 전용)과 번역(제목·나레이션·자막 편집)을 나란히 둔다. 선택 목록에는 언어별 번역된 장면 수를 표시한다. 상단 막대에 번역 제목, 번역 수, 남은 장면 번역 버튼, 진행 중 취소를 둔다. 장면별로 ‘번역 없음’·‘원본 수정됨’ 상태와 ‘번역/다시 번역’ 버튼, 경고, 접힌 역번역을 보인다. 번역을 고치면 경고를 다시 계산한다.
- 번역은 장면을 나눠 순서대로 요청하고 끝난 묶음부터 저장한다. 취소·실패 시 끝난 장면은 남기고, 취소 뒤 도착한 응답은 버린다. 데모 모드에서는 번역 버튼 대신 AI 연결 버튼을 보인다. 번역 텍스트는 싱할라·크메르 글꼴을 번들에서 불러와 시스템 글꼴이 없는 PC에서도 표시한다.
