# EduFlow 진행 현황 및 다음 방향 제안

작성일: 2026-09-29  
용도: 팀 진행 상황 공유 및 다음 개발 단계 합의

## 1. 회의에서 먼저 공유할 결론

EduFlow는 현재 **핵심 작업 흐름을 검증할 수 있는 UX 프로토타입**까지 완성되었다.

사용자는 원고를 입력하고 생성 조건을 설정한 뒤, 장면별 결과를 검토·편집·재생성하고 Markdown·CSV로 내보낼 수 있다. 자동 저장과 모바일 대응도 포함되어 있어 실제 사용 흐름을 시연할 수 있다.

다만 현재 생성 결과는 외부 AI가 아니라 원문을 규칙에 따라 나누는 **원문 발췌 데모**다. 따라서 아직 “AI가 교육 원고를 좋은 스토리보드로 바꾼다”는 제품의 핵심 가설은 검증되지 않았다.

> 다음 목표는 기능을 더 많이 붙이는 것이 아니라, 실제 AI 생성 품질을 측정할 수 있는 기준을 만들고 한 번의 전체 흐름을 실제 모델로 완성하는 것이다.

## 4. 권장 제품 방향

### 제품 정의

EduFlow를 범용 영상 생성 도구로 넓히기보다 다음 문제에 집중한다.

> 교육 기획자가 원고를 근거로 제작 가능한 스토리보드·나레이션·자막 초안을 빠르게 만들고, 장면 단위로 검토하여 사용자가 이를 수정, 활용할 수 있도록 하는 도구

### 핵심 경험

```text
원고와 조건 입력
    ↓
근거가 연결된 장면 초안 생성
    ↓
사람이 검토·수정·부분 재생성
    ↓
제작 가능한 구조로 내보내기
```

### 지금 지켜야 할 원칙

1. **원문 근거 우선**: 그럴듯한 문장이 아닌, 원문의 어디에서 어떤근거로 적용한 내용인지 확인할 수 있어야 한다.
2. **부분 수정 비용 최소화**: 전체를 다시 만들지 않고 필요한 장면만 고칠 수 있어야 한다.
3. **MVP구현 우선**: 로그인, 협업, 이미지 생성 같은 확장 기능은 생성 품질과 시간 단축을 확인한 후 판단한다.

## 5. 다음 단계 제안

### 1. AI 평가 기준

- 전체 생성과 선택 장면 재생성의 입력·출력 계약
- 원문 분할, 근거 식별자와 인용 허용 범위
- 대상·난이도·톤·키워드가 결과에 반영되는 규칙
- 장면당 하나의 중심 메시지와 원문 전개 순서 유지 규칙
- 나레이션과 자막의 역할, 길이, 중복 허용 기준
- 검토 필요 판정과 검토 사유의 분류
- 모델 평가표와 통과 기준

완료 기준: 같은 원고를 누가 평가해도 대체로 같은 기준으로 통과·실패를 판단할 수 있다.

### 2. 실제 AI 수직 흐름 연결

전체 기능을 한꺼번에 고도화하지 않고, 한국어 교육 원고 한 유형을 기준으로 다음 흐름을 먼저 완성한다.

1. 서버 전용 모델 어댑터 
    (서버 전용 모델 어댑터는 API 키를 노출하지 않고, EduFlow 서버에서 AI 모델을 안전하고 일관된 방식으로 호출하는 연결 코드입니다.)
2. 구조화 응답과 스키마 (불완전한 정보에 대한 보완성능) 검증
3. 전체 스토리보드 생성
4. 선택 장면 재생성
5. 기존 결과 보존과 사용자 오류 안내
6. 비용·응답 시간·데이터 전송 범위 기록

완료 기준: 대표 원고 한 건을 실제 모델로 생성하고, 편집·부분 재생성·내보내기까지 중단 없이 수행할 수 있다.

###  3. 품질과 안정성 검증

최소 5개의 서로 다른 실제 교육 원고로 아래를 평가한다.

- 핵심 내용 누락·왜곡
- 장면 구분과 교육 흐름
- 대상·난이도 적합성
- 화면 설명의 제작 가능성
- 나레이션 자연스러움
- 자막 길이·가독성·의미 일치
- 원문 근거 정확성
- 목표 시간 적합성
- 실패 시 원고·편집 결과 보존

완료 기준: 중대한 원문 왜곡 0건, 필수 항목 충족 100%, 대상·난이도 적합성 평균 4/5 이상을 목표로 한다.


## 8. 지금 보류할 기능

다음 기능은 매력적이지만 핵심 가설 검증 전에는 우선순위를 낮춘다.

- 로그인, 조직, 역할과 권한
- 서버 프로젝트 목록과 영구 저장
- 실시간 공동편집, 댓글, 승인 흐름
- PDF·DOCX 및 여러 참고자료 입력
- 이미지 생성·검색, TTS, 실제 영상 렌더링
- 완전한 RAG와 인터넷 자료 검색
- 결제와 사용량 과금

팀 협업 기능 역시 내부 파일럿에서 “파일 공유만으로 부족하다”는 증거가 나온 뒤 설계하는 것이 좋다.

## 11. 권장 회의 진행 순서

총 30분 기준이다.

1. 5분 — 현재 프로토타입 시연: 원고 입력 → 생성 → 편집 → 내보내기
2. 5분 — 현재 한계 공유: 실제 AI와 품질 검증은 미구현
3. 10분 — 첫 지원 원고 유형, 평가 원고 5개, 품질 기준 합의
4. 5분 — 모델 후보·데이터 정책·비용 상한 논의
5. 5분 — Gate 1 담당자와 완료 조건 확정

회의 종료 시 최소한 다음 세 가지가 정해져야 한다.

- 첫 번째로 잘 만들 교육 콘텐츠 유형
- 품질을 평가할 실제 원고와 평가자
- `03_AI_SPEC.md` 작성 및 승인 담당자

## 12. 팀 공유용 짧은 메시지

> EduFlow는 원고 입력부터 장면 편집·내보내기까지의 UX 프로토타입을 완성했습니다. 반복 사용성을 높이기 위해 큰 소개 영역을 줄이고 작업 화면 중심으로 정리했으며, 자동 저장과 모바일 흐름도 확인했습니다. 현재 생성은 실제 AI가 아닌 원문 발췌 데모이므로 제품의 핵심 가설인 생성 품질과 시간 단축은 아직 검증 전입니다. 다음 마일스톤은 기능 확장이 아니라 AI 생성 명세·평가 기준을 확정하고, 한국어 교육 원고 한 유형에 실제 모델을 연결해 품질을 검증하는 것입니다.
