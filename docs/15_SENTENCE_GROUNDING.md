# 장면별 문장 근거 검증

2026-11-02 적용. 기존 원고, 저장 초안, 지식베이스 원본과 색인을 삭제하거나 다시 작성하지 않는다.

## 시각자료 별도 선별 추가

글 근거는 전체 최대 20개 쌍, 시각자료는 별도의 최대 20개 쌍으로 같은 검증 호출에서 대조한다. 각 경로에서 모든 장면의 첫 후보에 우선 기회를 주고, 시각자료는 후보당 관련성 판정 하나만 요청한다. 동일한 근거와 장면 문맥은 입력에서 한 번만 전달한다. 최대 두 번의 제공자 호출과 기존 토큰·비용·시간 한도는 유지한다.

그림에 연결 정보가 없으면, 같은 페이지의 검색 가능한 원문 블록에 그림 제목이 실제로 있는 경우에만 캡션 후보를 만든다. 원본 그림 ID·페이지·크롭 좌표를 유지하며 기존 색인이나 KnowledgeLink를 변경하거나 verified 상태를 만들어 넣지 않는다. 기존 pending/rejected 연결, 미판독·검색 제외 페이지, 원문에 없는 제목은 승격하지 않는다. 후보는 association=caption으로 구분하며 기존 자료도 재등록 없이 조회 시 적용된다.

시각자료의 작업·장비·절차 관련성을 글의 사실 근거와 별도로 판단한다. 카메라 구도·배치까지 같을 필요는 없지만 일반적인 안전 주제만 같으면 제외한다. 원문 캡션·연결 설명 또는 표의 행과 머리글을 사용하며 이미지 픽셀을 다시 판독한 것으로 표시하지 않는다. 관련성을 통과한 개별 자료만 추천하고 visual_reference와 visualId로 기록한다. 이 판정으로 나레이션의 사실 근거를 만들지 않는다. 캡션을 사용한 그림에는 원본 확인 안내를 표시한다.

등록 자료의 52페이지 측정점 그림, 54페이지 환기장치 그림, 58페이지 급기 가이드 그림·표가 로컬 후보 검색에 들어오는 것을 확인했다. 이는 검색 재현이며 실제 유료 모델의 판정 결과는 아니다. 자동 검사에서는 독립 후보 보존, 기존 제외 결정 유지, 판정 실패 시 추천하지 않음, 개별 자료 선택, 저장·복원 및 두 호출 안의 전체 생성을 확인한다.

## 글 근거 생성과 연결 흐름

1. 선택한 PDF 페이지/원고를 로컬에서 교육 단위로 나눈 뒤 생성 **전에** RAG를 검색한다. 최대 12개 교육 단위를 고르게 뽑고, 단위별 검색 후보 24개를 재정렬해 전체 최대 12개 구절을 생성 AI에 제공한다. 원문이 교육 범위를 정하며 관련 없는 위험작업으로 주제를 확장하지 않는다.
2. AI는 원문만으로 기본 장면을 완성하고, RAG의 새로운 이유·설명·사례는 `supplements`에 출처 ID와 한 문장씩 별도 제안한다. 기본 나레이션에 외부 설명을 섞지 않도록 지시한다. 서버는 기본 본문과 보충 제안을 분리해서 유지하며 보충 제안을 바로 저장하지 않는다. 모델의 기본 본문이 원문만을 사용했는지는 프롬프트에 의존하므로 최종 원문 대조는 여전히 필요하다.
3. 기본 장면의 제목·나레이션·자막·화면 설명·시각자료 제안·원문 인용으로 장면별 추가 검색을 한다. 보충 제안은 검색어에 넣지 않는다. 장면마다 최대 24개 후보에서 글 근거 2개와 시각자료 2개를 각각 고르고, 생성 전 후보와 함께 검증 후보를 고른다. 제안한 보충의 출처는 적합성 필터 통과 후 우선한다. 현재 재정렬은 규칙 기반이며 학습된 Cross-Encoder 모델은 아니다.
4. 복합 주제 페이지는 관련된 완전한 문장별로 적합성을 평가한다. 페이지의 다른 문단에 위험요인이 있다는 이유만으로 전체를 제외하지 않는다. 기존 출처 ID·원본 페이지·블록 ID·검색 구절을 보존하며 제목·절·표 머리글은 별도 문맥으로 제공한다.
5. 장면당 최대 2개, 전체 최대 20개 장면/구절 쌍을 별도 AI 호출 한 번으로 대조한다. 모든 장면의 첫 후보에 우선 기회를 준다. 각 문장을 독립적으로 `supported`/`unsupported`/`conflict`로 판정해 같은 장면의 다른 문장이 맞지 않는다는 이유로 유효한 문장까지 거부하지 않는다. 원문과 같은 내용의 독립 확인도 허용한다. 응답에는 supported/conflict 문장만 담고 unsupported 문장은 생략해 반복 출력을 줄인다. 대조한 pair 자체는 항상 반환하며 모두 unsupported이면 matches는 빈 배열이다. 누락된 pair는 정상적인 부정 판정과 구분하여 응답 오류로 기록한다. 그림·표가 없는 근거에는 화면 설명·시각자료 제안 검증을 요청하지 않는다. 보충은 원문 범위 안에 있어야 하고, 원문 조건·수치와 충돌하면 제외한다.
6. 서버가 문장 ID·정확한 위치·인용 구절의 실제 포함 여부와 알려진 적용 조건·행동·시점·부정·숫자를 재검사한다. ‘작업 전’만 있는 근거로 ‘작업 전과 작업 중’을 인정하지 않고, 운전 정지를 전원 차단으로 인정하지 않는다. 단순한 부정 단어 유무로 동의 표현을 거부하지 않는다. 이 규칙은 모든 의미 관계를 보장하는 분류기는 아니다.
7. 통과한 문장에만 출처를 연결하며 보충 제안은 지정한 출처가 문장 전체를 뒷받침할 때만 기본 본문 뒤에 추가한다. 실패·생략·한도 초과로 검증하지 못한 제안은 폐기한다. 제거된 보충 때문에 뒤 문장의 위치가 바뀌면 출처 연결 위치도 다시 계산한다. 표·그림은 화면 설명 또는 시각자료 제안의 대조를 통과한 출처에서만 추천한다. 검색 후보 이력과 검증된 장면 근거는 따로 보관한다.

## 실패·비용 처리

- 생성 후 장면별 검색은 최대 2개 작업을 동시에 실행하며 같은 질의는 요청 안에서 재사용한다. 전체 검색 제한 시간은 10초다. 한 장면이 지연·실패해도 이미 완료한 다른 장면의 결과는 유지한다. 검색 실패와 적합한 결과 없음은 구분한다. 보수적인 로컬 필터와 후보 상한 때문에 적합한 근거를 놓칠 수 있으며 연결을 강제하지 않는다.
- 생성 전 검색은 별도의 10초 한도를 사용한다. 이 단계가 실패하면 원문 기반 생성 및 생성 후 장면별 근거 검색을 계속하며 새 보충은 제안하지 않는다.
- 검색 대기 전후로 문서 삭제·비활성화·수정 여부를 재검사한다. 같은 동기 처리 구간에서는 목록·구조를 재사용해 반복 조회 비용을 줄인다.
- 저장된 전체 검색 이력은 최대 100개까지 허용해 장면별 글·시각자료 후보를 보존한다. 기존 초안은 그대로 읽을 수 있다.
- 생성과 검증은 같은 보호된 어댑터, 같은 영구 비용 장부, 같은 요청 예약액 및 일/월 상한을 사용한다. 기존 최대 2회 호출 한도를 늘리지 않았다.
- 1차 생성이 유효하면 남은 1회를 검증에 사용한다. 형식 보정에 2차 호출을 사용했으면 검증을 생략하고 보충 제안도 제외한다. 후보가 없으면 검증 호출도 없다.
- 검증 입력도 별도로 토큰 수를 측정한다. 입력 상한 초과, 공급자 오류, 검증 시간 초과(60초), 잘못된 응답이면 출처를 연결하지 않고 원문 기반 결과를 유지한다. 사용자 취소와 전체 요청 시간 초과는 계속 요청을 중단한다.
- 검증 제한은 20초에서 60초로 조정했다. 스토리보드 전체 처리 제한은 180초, 생성 전 검색(최대 10초)을 포함한 브라우저 대기 제한은 195초다. 개별 제공자 요청의 기존 90초 제한은 유지한다. 호출 수·입력/출력 토큰·비용 한도와 취소 처리는 그대로 적용한다.
- 비용 장부는 기존과 같이 실제 청구액 대신 호출당 보수적 비용 상한을 기록한다. 미실행 호출의 예약액만 반환한다.

## 화면·저장

각 근거 카드에 문서·절·표 머리글, **정확한 나레이션/자막 문장 → 근거 구절 → 뒷받침하는 이유 → 활용 종류**를 표시한다. ‘AI 대조 통과’는 AI 판정이며 사람의 최종 사실 검토를 대체하지 않는다.

`scene.grounding`에 검증 상태·문장별 연결과 검색/대조/제외/충돌/보충 추가·제외 수를 저장한다. 검색 결과 없음, 후보 필터 제외, AI 대조 후 제외, 검증 실패를 다른 안내로 표시한다. 나레이션·자막·장면 문맥을 수정하면 이전 기록을 보존하면서 ‘재검증 필요’로 바꾼다. 재생성 시 다시 검증한다. 이전 초안에는 새 필드를 강제하지 않고 ‘이전 연결 기록 · 문장별 의미 검증 전’으로 표시한다.

실패 시 `scene.grounding.failures`에 생성 전 검색/장면별 검색/AI 검증 단계, 허용된 원인 코드, 기록 시각, 소요 시간과 확인 가능한 제한 시간·입력 토큰 수를 저장한다. 검색 오류·검색 시간 초과, 검증 시간 초과, 입력/출력 한도, 응답 형식·판정 누락, 호출 한도, 인증·설정·비용·서비스 오류를 구분한다. 원본 SDK 오류 문자열·API 키·원문 내용은 오류 기록에 넣지 않는다. 원인 기록은 초안 저장·복원에도 유지되며 과거 실패의 원인을 추측해 채우지 않는다.

일부 검색이 실패했어도 완료된 검색과 통과한 근거는 유지한다. 공유 검증 호출 실패는 실제 대조 대상으로 포함된 장면에만 기록한다. 실패한 단계가 있으면 통과한 근거 카드 옆에도 안내한다. 사용자 취소와 전체 요청 시간 초과는 기존처럼 요청을 중단하며 검증 오류로 삼켜서 성공 결과를 저장하지 않는다. 이 기록만으로 과거 오류의 원인을 복구할 수는 없다. 이후 20초 제한 문제를 보완하며 검증 제한을 60초로 조정했고, 시간 초과 기록에 전체 대조 쌍·문장 수도 추가했다. 호출·비용 한도는 유지한다.

## 검증

자동 검사에는 생성 전 RAG 전달, 보충 문장의 승인·제외 및 위치 복구, 검증 실패·형식 보정 시 원문 유지, 기존 초안 호환성이 포함된다. 잘못된 사고 단계 연결, 일부 행동만 지지, 부정·수치 불일치, 취소·비용 한도, 장면별 독립 검색, 검색 결과 부분 보존, 20장면 검증 기회, 6개 초과 출처 저장을 확인한다.

실제 등록된 자료 검색과 AI 의미 대조는 별도의 소규모 평가로 확인한다. 수작업으로 기대 결과를 지정한 기계사고·중량물 예방·호흡기 조건·온열질환 조건·직접 대응 근거·무관 자료를 사용한다. 전체 한국어 안전교육 자료에 대한 정밀도·재현율을 입증하는 벤치마크는 아니다.

```sh
node --conditions=react-server --import tsx scripts/eval-scene-grounding.ts
# 실제 연결 모델을 사용하는 경우: 기존 비용 한도 적용, 검증 요청 한 번
node --env-file=.env.local --conditions=react-server --import tsx scripts/eval-scene-grounding.ts --live
```

결과는 `output/scene-grounding-local.json`, `output/scene-grounding-live.json`에 저장한다. 로컬 실행은 AI 의미 대조를 수행한 것으로 표시하지 않는다. 평가 보고서에는 API 키나 실제 사용자 초안을 기록하지 않는다.

이전 구조의 2026-11-02 실연결 평가(현재 보충 생성 흐름의 실연결 검증은 아님): 5개 사례 모두 기대 결과와 일치했다. 중량물 예방·호흡기 조건·온열질환 조건·무관 자료는 연결 0개였고, 직접 대응 근거는 별도 AI 호출 1회로 나레이션·자막 5문장이 연결됐다. 실제 등록 자료를 기계사고 대응 장면으로 검색한 결과에서는 조건 대조 후 적합한 후보가 남지 않았다. 이는 자료 전체에 관련 내용이 전혀 없다는 뜻이 아니라 현재 검색·필터 범위의 결과다.

첫 실연결 검사에서는 검증 AI가 온열질환 응급조치를 기계사고에도 인정하는 오판이 발견됐다. 이후 원문·근거의 적용 조건을 서버에서 추가로 확인하도록 수정한 결과다. 모델 판정만으로 정확성을 보장하지 않는다.

## 적용 범위 분류 (2026-11-02)

문장-출처 연결에 `applicability`를 별도로 저장한다. `direct`는 대상·행동·작업 단계·조건이 직접 일치하는 근거, `transfer`는 다른 대상 자료에서 활용하는 공통 원칙이다. 기존 `value`(내용 확인/설명/사례/시각자료)는 활용 용도이며 적용 범위와 혼용하지 않는다. 이전 기록에 분류가 없으면 ‘적용 범위 미분류’로 표시한다.

기존 두 번째 검증 호출에서 분류와 원래 대상·현재 대상·공통 원칙·확인할 조건을 판정한다. 다른 장비의 의무·수치·고유 절차를 옮기거나 시점·점검 대상을 바꾸는 연결은 간접 활용으로 구제하지 않는다. 시각자료에는 다른 장비의 유추 활용을 허용하지 않는다. 검증 호출 수와 비용 상한은 그대로 유지한다. 분류 필드가 누락된 새 응답은 검증 실패로 처리한다.

새 transfer 보충 문장은 `grounding.suggestions`에 보관하며 나레이션·자막에는 자동 반영하지 않는다. 작업자의 ‘조건 확인 후 본문에 반영’에서 본문·오프셋·검토 상태를 한 번에 갱신한다. 이미 원문 기반 본문에 있던 문장의 간접 출처는 문장을 바꾸지 않고 ‘적용 조건 확인 완료’만 기록한다. 확인 후에도 transfer 분류는 유지한다. 장면 수정으로 stale이 되면 이전 제안을 반영할 수 없고 재생성이 필요하다. 제외/보류 판정은 `grounding.decisions`에 문장·출처·이유와 함께 남긴다.

화면·브라우저 저장·Markdown/전체 복사·PDF에 분류와 조건을 유지한다. 확인 전 제안의 근거는 스토리보드 이미지 생성 입력에서 제외한다. 기존 스토리보드를 자동 재작성하거나 새 기준으로 소급 승인하지 않는다. 자동 테스트는 판정 응답을 제어한 기능 검증이며 실제 AI의 의미 판정 정확도를 보장하는 평가는 아니다.
