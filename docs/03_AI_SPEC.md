# EduFlow 생성 응답과 실패 처리 명세

계약 버전: `eduflow-generation-v1`

현재 실행 방식: 서버 설정에 따른 무료 원문 발췌 데모 또는 실제 OpenAI 생성. PDF의 표·그림 해석은 실제 AI 모드에서 지원한다.

## 1. 요청과 원문 구간

`POST /api/generate`는 원고, 생성 설정, 선택적인 기존 장면과 재생성 요청을 받는다. 원고는 공백 제외 100자 이상, 전체 20,000자 이하이다. 요청 본문 전체는 150,000자 이하이다. 재생성 대상의 ID는 기존 장면의 UUID여야 한다.

PDF 생성은 `multipart/form-data`의 `input` JSON과 `pdf` 파일을 받는다. `input.pdfSource`에 파일명과 정렬된 원본 페이지 번호를 넣고, `pdf`에는 해당 페이지만 복사한 PDF를 순서대로 보낸다. PDF가 있으면 원고는 선택적인 추가 설명이므로 100자 최소 조건을 적용하지 않는다. JSON 필드는 150,000자 이하, 선택 PDF는 50MB 미만이며 서버는 PDF 유효성과 선택 페이지 수 일치를 확인한다. 실제 원본 페이지 번호와 PDF 순서는 브라우저의 복사 과정에서 대응시키며 서버는 원본 전체를 받지 않는다. 파일 없는 PDF 메타데이터 요청과 데모 모드 PDF 생성은 차단한다.

전체 생성은 지정된 3~20개 장면을 반환한다. 자동 선택은 현재 데모와 동일하게 `영상 길이(분) × 2`, 최소 3개·최대 12개로 정한다. 선택 장면 재생성은 정확히 1개를 반환한다.

서버의 `manuscriptSource()`가 제목과 본문 문장을 구분한다. 모델에 본문 문장 목록과 `sentence:1-1` 같은 식별자를 함께 제공한다. 여러 문장을 인용할 때는 `sentence:1-3`처럼 시작·끝 문장 번호를 사용한다. 원고 내용은 자료로 취급하고 그 안의 명령을 실행하지 않도록 생성 지시에 명시한다.

PDF는 서버에서 페이지별로 분석한다. 단순하고 읽는 순서가 확실한 글은 `document.textPages`의 `{ page: 원본번호, text: 추출원문 }`로 보낸다. 벡터·이미지·스캔·표·복잡한 배치·불확실한 글자는 페이지 전체를 최대 1536×2048픽셀로 고정한 호환 PDF 하나로 묶어 Responses API의 `input_file`로 보낸다. 이 첨부의 순서는 `document.visualPages`의 원본 번호와 대응하며 전체 선택 번호와 혼동하지 않는다. 텍스트 전용 입력은 PDF 첨부가 없다. 시각 페이지의 `detail: high`, 잘림 영역·회전 보존과 별도 `input_image`를 보내지 않는 정책은 유지한다. 추출 실패 시 기존 시각 경로를 사용한다. 입력 토큰 계산·생성·보완은 같은 요청 범위의 추출 결과와 호환 PDF 바이트를 재사용한다. 선택하지 않은 페이지는 포함하지 않는다. PDF 근거는 `pdf-page:원본번호` 하나와 해당 페이지의 직접 인용 또는 보이는 표·그림 설명으로 작성한다. 서버는 선택 페이지에 속하는 식별자인지 확인하며 시각적 내용의 사실 검증은 수행하지 않는다. 원본 대조 안내와 검토 필요 표시는 유지한다.

### 구조화된 표와 연결 이미지

`document.layoutPages`는 원본 번호·페이지 크기·바깥 원문·표·설명 상자·그림 연결·전체 배치 이미지 ID를 보존한다. `tables`는 원본 좌표 기준 행/열 경계, 셀의 1부터 시작하는 행/열과 `rowSpan`/`colSpan`을 갖는다. 전송 시 셀은 `cellFields` 순서 배열로 압축하며 빠진 끝 항목은 빈 문자열/빈 배열이다. `emptyCells: implicit`인 표는 명시되지 않은 나머지 단위 격자가 빈 셀이다. 빈 병합 셀은 별도로 유지한다. 빈 칸을 체크 여부로 해석하지 않는다.

고화질 `input_image`는 원본 페이지·그림 ID·해당 셀과 연결된다. 셀 바깥 그림은 페이지 좌표·주변 원문과 연결하며 셀 관계를 확정하지 않는다. 중립 배경 상자의 원문·좌표·색과 강조 구간은 구조로 보존한다. 축소된 전체 페이지 이미지는 표 바깥 머리글과 이어지는 문맥을 확인하는 용도다. 복잡한 도형, 표 경계 불확실, 큰 스캔 이미지, 회전·불확실한 글자·지원하지 않는 그리기 명령은 전체 페이지 PDF로 유지한다.

계산·생성·형식 보완은 동일한 준비 결과와 이미지 바이트를 재사용한다. 전체 페이지 PDF와 분리 이미지의 합계 50MB 미만 및 분리 이미지 400개 상한을 적용한다. 상한을 넘길 후속 페이지는 전체 페이지 경로로 유지한다. UI/저장/재시도 흐름은 변경하지 않는다. 이 최적화는 변환 PDF를 사용하며 HWP·PPTX 원본 표 객체를 직접 추출하는 기능은 아니다.

장면 재생성 요청의 `sceneSourceScope`는 `citation` 또는 `selection`이다. UI는 출처가 확인되면 `citation`을 기본 선택하며 해당 페이지로 입력 PDF를 먼저 줄인다. 현재 문서명·선택 페이지·기존 장면의 문서 출처가 맞지 않으면 전체 선택 범위를 사용한다. 다른 페이지를 참고하는 수정은 사용자가 `selection`을 선택한다. 이 필드가 없는 이전 클라이언트도 전체 선택 범위를 사용한다. 원본 선택과 저장된 장면은 변형하지 않는다.

## 2. 생성 모델이 반환할 양식

`generationTask()`는 생성 지시, 원고 구간, 설정, 요청 장면 수, 기존 선택 장면, 추가 요청, JSON Schema를 제공한다. 어댑터는 아래 형태의 JSON 객체 또는 해당 객체의 JSON 문자열을 반환한다. Markdown 코드 블록은 허용하지 않는다.

```json
{
  "title": "콘텐츠 제목",
  "summary": "핵심 요약",
  "objectives": ["학습 목표"],
  "scenes": [{
    "sceneNo": 1,
    "title": "장면 제목",
    "purpose": "학습 목적",
    "visual": "화면 설명",
    "assets": "시각 자료 제안",
    "narration": "나레이션 초안",
    "subtitle": "자막 초안",
    "duration": 30,
    "evidence": "원문의 직접 인용",
    "sourceId": "sentence:1-1"
  }]
}
```

| 항목 | 규칙 |
| --- | --- |
| 콘텐츠 제목 / 요약 | 비어 있지 않은 문자열, 최대 160 / 20,000자 |
| 학습 목표 | 비어 있지 않은 문자열 1~5개, 각각 최대 1,000자 |
| 장면 번호 | 1부터 요청 장면 수까지의 정수, 중복·누락 불가 |
| 장면 제목 / 목적 | 비어 있지 않은 문자열, 최대 160 / 1,000자 |
| 화면 설명 / 자료 제안 | 비어 있지 않은 문자열, 최대 5,000 / 3,000자 |
| 나레이션 / 자막 | 비어 있지 않은 문자열, 최대 24,000 / 2,000자 |
| 예상 시간 | 1~600초의 정수 |
| 근거 / 구간 식별자 | 필수 문자열 항목, 최대 20,000 / 80자. 불확실하면 빈 문자열 허용 |
| 전체 모델 응답 | JSON 문자열 기준 최대 1,000,000자 |

정의하지 않은 항목을 모델 응답에 추가하면 검증 실패로 처리한다. ID·검토 상태·수정 기록·설정·생성 방식·모델 정보는 모델에게 맡기지 않는다.

## 3. 검증·보완·근거 확인

1. 서버가 JSON, 필수 항목, 길이, 장면 수, 중복 장면 번호를 검사한다.
2. 형식 오류가 있으면 같은 요청에서 최대 한 번 보완한다. 어댑터에 오류 위치·종류, 이미 검증된 장면과 개요를 제공한다. 오류 정보에 원고나 원시 오류 메시지를 넣지 않는다.
3. 개요와 장면 수가 올바른 응답에서는 정상 장면을 번호별로 보존한다. 두 번째 응답의 순서가 바뀌거나 기존 정상 장면이 다시 잘못되어도 보존한 정상 장면을 유지한다.
4. 모든 장면을 완성해야 성공한다. 두 번의 응답으로도 완성하지 못하면 502 오류를 반환하고, 화면의 기존 결과를 유지한다. 미완성 새 초안을 화면에 적용하지 않는다.
5. 인용문을 지정된 원문 문장 구간과 공백을 제외하고 대조한다. 근거 누락·알 수 없는 구간·인용 불일치는 장면의 검토 사유와 생성 기록의 경고로 표시한다. 근거가 불확실하다는 이유만으로 모델 호출을 반복하지 않는다.

인용 일치 검사는 사실 검증·왜곡 검증·나레이션과 자막의 의미 검증을 대신하지 않는다. 모든 생성 장면은 서버가 `review: true`, `edited: []`로 설정한다. 최종 검토 완료 표시는 사용자가 결정한다.

### 코드 기반 용어 교정

AI 모드에서는 형식 검사·필요한 보완이 끝난 뒤, 반환 직전에 `lib/term-corrections.ts`의 확인된 오타 목록으로 생성 문구를 검사한다. 초기 등록 규칙은 `껴임 → 끼임` 하나이며, 조사와 정해진 복합어가 붙은 `껴임을`, `껴임이란`, `껴임사고`, `껴임재해예방`도 처리한다. 일반 맞춤법 검사나 유사 단어 추정은 하지 않는다. 호롱불에서 용어를 확인받으면 목록을 확장한다.

대상은 콘텐츠 제목·요약·학습 목표와 장면 제목·목적·화면 설명·자료 제안·나레이션·자막이다. 원문 근거 `evidence`, 출처 `sourceId`, 원고·설정·원본 PDF는 교정하지 않는다. 생성 문구 안의 URL·이메일·파일명·코드도 유지한다. 이름·알 수 없는 단어 안의 부분 일치에는 적용하지 않는다. 데모 발췌, 기존 저장 자료, 사용자 직접 편집에는 적용하지 않고 새 AI 생성과 장면 재생성 결과에만 적용한다.

교정한 단어 쌍·필드·횟수를 장면의 검토 사유에 기록하고 전체 기록은 `generation.warnings`에 요약한다. 화면 상단에서 전체 생성 당시의 교정 내역을 보여주며 장면별 내역은 검토 사유에 남긴다. 기존 저장·Markdown·CSV 형식으로 교정 결과와 기록을 보존한다. 부분 재생성은 해당 장면의 새 기록만 적용하고 다른 장면은 유지한다. 기록은 생성 당시 내역이므로 이후 수동 편집에 맞춰 다시 계산하지 않는다. 교정으로 검토 완료 상태를 자동 설정하지 않는다.

이 처리는 로컬 코드만 실행하며 프롬프트·모델 입력을 추가하거나 AI 호출을 늘리지 않는다. 따라서 용어 검사 자체의 추가 토큰은 0이다. 등록하지 않은 오타, 문맥 오류, 수치·사실 오류, PDF 문자 인식 전체의 정확성을 해결하지는 않는다.

## 4. 성공 응답과 저장 호환

성공 HTTP 응답은 편집 화면에서 사용하는 Board 형식이다. 서버가 전체 생성의 UUID를 발급하고, 부분 재생성에서는 요청한 장면의 UUID를 유지한다. 설정과 `mode`는 요청과 선택된 어댑터에서 가져온다.

`generation`에는 계약 버전, 모델, 프롬프트 버전, 생성 시각, 호출 횟수, 보완된 장면 번호, 검토 경고를 기록한다. 각 장면에도 생성 모델·버전·시각·호출 횟수·방식을 기록하므로 부분 재생성의 기록을 유지한다. Board 수준의 기록은 전체 생성 당시의 기록이다. Markdown·CSV 내보내기에도 생성 기록을 포함한다.

브라우저는 필수 내용, UUID 중복, 요청 장면 수, 설정 일치, 재생성 대상 ID, 검토 상태와 생성 기록을 한 번 더 검사한 후 결과를 적용한다. 저장·편집 검증은 별도로 유지한다. 기존 기록이 없는 데모, 사용자가 비워 둔 편집 필드, 직접 추가한 빈 장면을 계속 저장할 수 있다. 기존 `frame-studio-v1` 저장 키를 유지하며, 복구할 수 없는 원본은 덮어쓰지 않는다.

## 5. 실패 응답과 재시도

오류는 `{ "code": "TIMEOUT", "error": "사용자 안내", "retryable": true }` 형태로 반환한다. 성공·실패 응답 모두 `Cache-Control: no-store`를 사용한다. 제공자의 원시 오류·원고·API 키를 응답이나 로그에 출력하지 않는다.

| 코드 | HTTP | 다시 시도 버튼 |
| --- | --- | --- |
| INVALID_REQUEST | 400 | 없음. 입력을 수정하고 다시 생성 |
| REQUEST_TOO_LARGE | 413 | 없음. 입력 분량을 줄이고 다시 생성 |
| RATE_LIMITED | 429 | 있음. 잠시 후 직접 재시도 |
| CANCELLED | 499 | 없음. 취소 안내와 기존 결과 유지 |
| INTERNAL_ERROR | 500 | 없음. 기존 결과 유지 |
| INVALID_OUTPUT | 502 | 있음. 자동 보완 1회 이후의 실패 |
| PROVIDER_UNAVAILABLE | 503 | 있음. 직접 재시도 |
| TIMEOUT | 504 | 있음. 직접 재시도 |

자동 재호출은 출력 형식 보완에만 사용하며, 한 HTTP 요청당 모델 호출은 최대 2회이다. 제공자 장애·호출 제한·시간 초과를 자동으로 반복하지 않는다. 브라우저는 하나의 HTTP 요청을 보내며 서버의 보완과 중복해서 자동 요청하지 않는다.

모델 호출과 보완을 합친 서버 생성 시간 제한은 90초이며, 브라우저 요청 제한은 전달 여유를 포함해 95초이다. 서버는 요청 취소와 시간 초과를 어댑터의 `AbortSignal`로 전달한다. 어댑터가 신호를 무시하더라도 서버의 대기는 제한 시간에 종료한다. 실제 제공자 요청을 중단하려면 어댑터가 반드시 이 신호를 네트워크 호출에 연결해야 한다.

직접 재시도할 때는 실패 당시의 원고·설정·장면·추가 요청을 사용한다. 이후 수정·삭제한 대상 장면을 덮어쓰지 않는다. 실패·취소·시간 초과에서는 기존 편집 결과를 변경하지 않는다.

PDF 재시도도 실패 당시 선택본 Blob과 원본 페이지 번호를 사용한다. 새 PDF를 불러오거나 다른 페이지를 선택해도 실패 요청의 파일 내용이 바뀌지 않는다. 선택 PDF는 브라우저 IndexedDB에 저장하고 메타데이터는 기존 저장 키에 포함한다. 원본 전체는 메모리에만 남으므로 새로고침 후 페이지 변경에는 원본 재업로드가 필요하다. 결과와 개별 장면의 `pdfSource`는 생성에 사용한 파일명·원본 번호를 보존하며 내보내기에 포함한다.

## 6. 실제 모델 연결 위치와 검증

현재 Route Handler는 `lib/server/generator.ts`에서 서버 설정에 따라 데모 또는 OpenAI 어댑터를 선택한다. 실제 모델 어댑터는 `GenerationAdapter`의 `mode`, `model`, `promptVersion`, `generate(input, context)`를 구현하고 Route Handler에서 선택한다. `context.task`의 JSON Schema와 원문 구간을 제공자에게 전달하고, `context.repair`의 정상 장면과 보완 항목을 다음 호출에 반영한다. API 키와 제공자 SDK는 서버 모듈에서만 사용한다. 제공자별 429·장애 응답은 대응하는 `GenerationError`로 변환한다.

OpenAI 어댑터, 토큰·비용 상한, 데이터 전송 안내와 모드별 진행 안내를 구현했다. 실제 키가 등록되어야 유료 호출을 시작할 수 있으며 실제 계정에서의 생성 성공·품질은 별도 확인이 필요하다.

키·비용 보호 1단계는 구현되어 있다. `createGenerateHandler()`는 AI 모드에 서버 전용 설정·로컬 접근·지속 장부에 의한 비용 예약을 적용한다. 잠금·설정 누락·접근 거부·예산 소진·장부 장애는 재시도 버튼 없이 기존 결과를 유지한다. 실제 어댑터는 전달받은 토큰 상한을 제공자 요청에 강제하고 SDK 재시도를 끈다. 설정 및 한계는 [로컬 키·비용 보호 안내](04_AI_SAFETY.md)를 따른다.

자동 검사: `npm run typecheck`, `npm test`, `npm run build`. 생성 테스트는 부분 보완, 정상 장면 보존, 빈 응답·중복·형식 오류, 원문 근거 경고, 취소·시간 초과, 안전한 오류 응답, 재생성 대상 일치, 기존 저장 호환을 검증한다. 실제 모델의 대상별 표현·번역·원문 충실도 품질은 연결 후 실제 원고로 평가한다.

## OpenAI 연결

`EDUFLOW_GENERATOR=openai`를 선택하면 서버 전용 공식 SDK가 Responses API를 호출한다. 모델은 `gpt-5.4-mini-2026-03-17`로 고정한다. Structured Outputs의 엄격한 JSON 스키마를 요청한 뒤 기존 서버 검사·근거 대조·부분 보완을 적용한다. 근거 대조는 직접 인용의 일치 검사이며 전체 내용의 사실성을 보증하지 않는다.

토큰 계산에도 OpenAI 네트워크 요청을 사용하므로 원고는 이 단계부터 전송된다. 최초 생성과 보완의 전체 입력(스키마·프롬프트·원문·선택 장면·보완 자료 포함)을 동일한 payload로 계산한다. 계산 장애·분량 초과 시 생성하지 않는다. 추론은 none, 출력은 최대 8,000토큰, 도구 없음, 표준 서비스 등급, SDK 자동 재시도 0이다. `store:false`로 응답 저장을 요청하지 않지만 OpenAI의 기타 데이터 보관 정책까지 없애지는 않는다.

거절·출력 잘림·키 권한/결제 오류는 별도 안전한 안내를 반환하고 자동 보완하지 않는다. 제공자 원본 오류 메시지는 표시하지 않는다. 브라우저의 형식 오류 자동 재호출도 없애 중복 과금을 방지한다. `GET /api/generate`는 모드와 설정 준비 여부만 반환하며 키를 노출하거나 실제 연결 성공을 보증하지 않는다.

기존 저장 키와 장면 편집 형식은 유지한다. 선택 장면 재생성 시 해당 장면의 생성 기록만 바꾸므로 데모·AI 장면이 함께 저장될 수 있으며, 화면은 선택 장면의 생성 기록을 기준으로 표시한다. 키 등록 후 실제 생성·선택 장면 재생성·저장/복구·내보내기는 추가로 확인해야 한다.
