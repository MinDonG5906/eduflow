## 1. 프로젝트와 사용자의 요청

사용자는 `01_MVP_PRD.md`를 제공하며 다음과 같이 요청했다.

이에 교육 콘텐츠 스토리보드 서비스의 작업 흐름을 체험할 수 있는 웹 프로토타입을 구현했다. 이후 사용자는 진행 상황과 다음 작업을 물었고, 마지막으로 GPT 채팅에서 이어서 사용할 인수인계 파일을 요청했다.

서비스의 현재 화면 이름은 **Frame / frame.**이다. 구현 과정에서 사용한 이름이며 사용자가 최종 브랜드로 확정한 것은 아니다.

### 제품이 해결하려는 문제

교육 기획자·강사·교육 담당자가 교육 원고를 영상 제작용 스토리보드로 정리하는 데 드는 시간을 줄인다. 장면별 화면 설명·시각 자료 제안·나레이션·자막·원문 근거를 일관된 형식으로 제공하고 사람이 검토한다.

### 핵심 사용자 흐름

원고 입력 → 생성 조건 설정 → 초안 생성 → 장면별 검토·수정 → 선택 장면 재생성 → 복사·내보내기

## 5. 데모와 실제 AI의 차이

현재 `POST /api/generate`는 `generateDemo()`를 실행한다. 외부 모델 요청도, 실제 AI API 키도 없다.

- 원고를 문장 단위로 나누고 요청한 개수만큼 장면에 배분한다.
- 제목·요약은 원문 일부를 이용하며 학습 목표는 정해진 문구다.
- 대상·난이도는 장면 목적과 검토 안내 문구에 반영된다.
- 톤앤매너는 나레이션 도입부 문구에 반영된다.
- 키워드는 시각 자료 제안에 메모로 반영된다.
- 추가 요청·재생성 지시는 화면 설명에 제작 메모로 반영된다.
- 영어 선택은 일부 안내 템플릿만 영어로 바꾼다. 한국어 원문의 실제 영어 번역은 하지 않는다.
- 자동 장면 수는 영상 길이에 기반한 규칙이다. 실제 학습 흐름을 판단하지 않는다.
- 장면 시간 합계는 목표 시간에 맞춰 나눠 배정한다. 실제 발화 속도로 검증한 시간은 아니다.
- 모든 장면은 검토 필요 상태이며, 사람이 검토 완료로 바꿀 수 있다.
- 화면의 일러스트는 공통 참고 이미지다. 장면 내용을 시각적으로 생성한 결과물이 아니다.

따라서 **“AI 생성 품질 검증 완료”, “대상별 실제 문체 조정 완료”, “영어 번역 구현 완료”, “모든 P0 인수 조건 통과”라고 설명하면 안 된다.**

### 핵심 데이터 구조

```ts
Settings = {
  audience, difficulty, minutes, count, tone,
  keywords, language, instructions
}

Scene = {
  id, title, purpose, evidence, sourceId,
  visual, assets, narration, subtitle,
  duration, review, reviewReason, edited
}

Board = {
  title, summary, objectives, scenes, settings,
  mode: 'demo'
}
```

- `count`: `'auto'` 또는 3~20의 정수.
- `duration`: 장면별 초 단위 정수. 전체 시간은 장면 합계로 계산.
- `sourceId`: `sentence:1-3` 등 원문 문장 구간 표시. 직접 추가한 장면은 `manual`.
- `edited`: 수정된 필드 이름 목록. 이전 원문 값이나 이력을 저장하는 구조는 아님.
- `mode` 스키마가 현재 `'demo'`만 허용하므로 실제 AI 연결 시 타입·검증·화면 표기를 함께 변경해야 함.
- 편집 중 빈 필드가 허용되는 스키마임. 실제 모델 결과용 필수 비어 있지 않은 값 검증과 편집 임시 상태 검증을 분리할 필요가 있음.

### API와 실패 처리

요청 본문은 `{ manuscript, settings, scene?, direction? }`이다. `scene`과 `direction`은 선택 장면 재생성에 사용한다.

클라이언트는 20초 요청 제한, AbortController 취소, 중복 실행 차단을 사용한다. **HTTP 성공 응답이 JSON으로 파싱되었지만 Board 스키마 검증에 실패한 경우** 최대 1회 추가 요청한다. HTTP 오류, JSON 파싱 오류, 서버 내부 생성 오류 전체를 자동 재시도하는 완전한 정책은 아직 아니다. 실제 모델을 연결할 때 서버·클라이언트의 재시도 책임을 정리해야 한다.

결과 전체가 검증되지 않으면 기존 작업을 보존한다. 성공한 장면만 부분적으로 보존하는 복구 구조는 없다. 재생성 성공 시 선택 장면의 ID를 기준으로 교체하고 다른 장면은 유지한다.

Turbopack 빌드는 해당 실행 환경에서 로컬 프로세스 통신 포트 권한 문제로 실패했다. `next build --webpack`으로 변경한 후 빌드가 통과했다. 개발 서버는 `next dev`를 사용한다.

## 9. 다음 작업 우선순위

다음은 권장 순서이며, 사용자에게 확정받은 일정·모델 선택·배포 승인이 아니다.

### 1순위: 실제 원고로 화면 흐름 확인

원고 입력 → 설정 → 편집 → 검토 → 내보내기 과정에서 필요한 필드·작업 순서·편집 단위를 확인한다. 큰 화면 재설계보다 실제 제작자가 필요한 정보를 찾고 수정할 수 있는지에 집중한다.

### 2순위: AI 생성 명세 작성

우선 `03_AI_SPEC.md` 초안을 작성하는 방향이 제안되었다. 원래 PRD의 후속 문서 순서는 `02_UX.md → 03_AI_SPEC.md → 04_TECH.md → 05_TASKS.md`이다. 현재 독립된 후속 명세 문서들은 작성되지 않았으므로 UX 결정이 필요하면 먼저 짧게 정리한다.

AI 명세에 필요한 내용:

- 전체 생성과 선택 장면 재생성의 입력·출력 계약.
- 대상·난이도·톤·키워드·출력 언어·추가 요청 반영 규칙.
- 원문 밖의 수치·사례·인물·단정적 사실을 추가하지 않는 규칙.
- 원문 분할과 인용 근거의 식별자·매칭 검증 방식.
- 나레이션과 자막 역할 구분, 자막 최대 두 문장.
- 장면당 중심 메시지 하나, 원문의 핵심 순서 유지.
- 시간 합계가 목표의 ±15% 이내인지 검증하고 조정하는 방법.
- 근거 부족·수치 확인·표현 검토 등의 상태 판별 기준.
- JSON 출력, 스키마 검증, 부분 실패, 재시도, 타임아웃, 결과 보존 정책.
- 모델 평가용 원고와 평가표, 통과 기준.

### 3순위: 실제 모델 API 연결

공급자·모델을 선택한 뒤 `/api/generate`에 서버 전용 어댑터를 연결한다. API 키는 브라우저에 포함하지 않는다. 데이터 전송 범위·보관 정책을 결정하고 안내한다. 실제 AI 응답용 스키마, 데모/AI 모드, 오류 처리, 비용·토큰·시간 제한을 함께 구현한다.

20초 클라이언트 제한은 실제 모델의 응답 시간과 PRD의 90초 목표에 맞춰 재검토한다. 외부 공개 배포 전에는 요청 남용·비용 제한도 설계해야 한다.

### 4순위: 생성 안정성과 편집 일관성 보강

실패한 장면만 표시·재시도하고 성공 장면을 보존한다. 재생성에 사용되는 설정이 기존 Board 조건과 다른 경우 결과 메타데이터가 일치하도록 정책을 정한다. 원고를 수정한 뒤 기존 장면 근거가 유효한지도 확인해야 한다. 필요하면 AI 원본 값과 사용자 편집 값을 구분해 보관한다.

### 5순위: 내부 테스트 배포와 인수 검증

실제 원고 최소 5개로 전체 흐름과 품질을 평가하고, 파일 내보내기·브라우저 호환성·오류 복구를 확인한다. 이후 PRD 인수 조건과 성공 지표에 따라 내부 테스트 가능 여부를 판단한다.

## 10. 현재 미결정 사항과 범위 제한

아직 정하지 않은 사항:

- 실제 모델 공급자·모델명, 사용 예산·비용 상한.
- 테스트용 실제 교육 원고 및 평가 담당자.
- 배포 플랫폼·공개 범위.
- 사용자 데이터 처리·모델 제공자 보관 정책.
- 데모 유지 여부, 원본/수정 이력 보관 수준.

이번 MVP의 핵심 범위 밖:

- 로그인·회원·조직·권한·결제.
- 서버 프로젝트 목록·영구 저장·실시간 공동편집.
- PDF/DOCX 파싱, 이미지 검색, 완전한 RAG.
- 실제 영상·음성·이미지 자동 생성.

위 기능들은 AI 생성과 검토 흐름 검증보다 앞서 추가할 필수 항목이 아니다. 사용자가 범위를 변경하면 다시 판단한다.

# 부록 A. 원본 MVP PRD 전문

# 교육 콘텐츠 스토리보드 생성 서비스 MVP PRD

> 문서 유형: 제품 요구사항 문서(Product Requirements Document)  
> 문서 상태: 초안 v0.1  
> 작성일: 2026-09-17  
> 기준 문서: `00_PROJECT_BRIEF.md`

## 1. 문서 목적

이 문서는 교육 원고를 AI로 구조화하고 장면별 스토리보드·화면 설명·시각 자료 제안·나레이션·자막 초안을 생성하는 첫 번째 웹 프로토타입의 범위와 완료 기준을 정의한다.

MVP의 핵심은 많은 기능을 구현하는 것이 아니라 다음 작업 흐름이 실제로 유효한지 검증하는 것이다.

> 원고 입력 → 생성 조건 설정 → AI 초안 생성 → 장면별 검토·수정 → 선택 장면 재생성 → 결과 내보내기

## 2. MVP 목표

### 2.1 제품 목표

1. 사용자가 교육 원고를 입력하고 10분 이내에 검토 가능한 스토리보드 초안을 얻을 수 있게 한다.
2. 대상과 난이도 설정이 어휘, 설명 깊이, 나레이션 및 자막에 실제로 반영되게 한다.
3. 생성 결과를 고정된 구조로 제공하여 담당자에 따른 산출물 형식 차이를 줄인다.
4. 사용자가 AI 결과를 장면별로 수정하고 필요한 부분만 다시 생성할 수 있게 한다.
5. 원문 근거와 검토 필요 항목을 표시하여 사용자가 AI 결과를 검증할 수 있게 한다.

### 2.2 검증 가설

| ID | 가설 | 검증 방법 |
|---|---|---|
| H-001 | AI 초안을 사용하면 수작업보다 최초 스토리보드 작성 시간이 단축된다. | 같은 원고의 수작업 시간과 MVP 사용 시간을 비교한다. |
| H-002 | 고정된 장면 구조를 사용하면 담당자별 결과물 형식 차이가 줄어든다. | 서로 다른 사용자의 결과에서 필수 항목 누락 여부를 비교한다. |
| H-003 | 대상과 난이도 설정을 변경하면 결과의 어휘와 설명 깊이가 구분된다. | 동일 원고를 서로 다른 설정으로 생성하여 평가표로 비교한다. |
| H-004 | 장면별 수정·재생성 기능이 전체 내용을 다시 작성하는 부담을 줄인다. | 수정이 필요한 장면만 고치는 작업의 완료 시간과 사용자 평가를 확인한다. |

## 3. 대상 사용자

### 3.1 주 사용자

- 교육 콘텐츠 기획자
- 강사 및 교육 담당자
- 전문 지식을 교육 영상으로 전환하는 실무자

### 3.2 보조 사용자

- 영상 제작자 및 편집자

### 3.3 사용자가 달성하려는 작업

- 긴 원고의 핵심 내용과 학습 목표를 빠르게 파악한다.
- 원고를 교육 흐름에 맞는 장면 또는 단계로 나눈다.
- 장면별 화면 구성, 나레이션 및 자막 초안을 한 번에 작성한다.
- 같은 원고를 서로 다른 학습 대상과 난이도에 맞게 변환한다.
- AI 결과를 검토·수정한 뒤 제작 담당자에게 전달한다.

## 4. MVP 범위

### 4.1 반드시 포함하는 기능(P0)

| 범주 | 기능 |
|---|---|
| 원고 입력 | 직접 입력·붙여넣기, TXT 파일 불러오기 |
| 생성 조건 | 대상, 난이도, 영상 길이, 장면 수, 톤앤매너, 강조 키워드, 출력 언어 설정 |
| AI 구조화 | 제목, 핵심 요약, 학습 목표 생성 |
| 장면 생성 | 장면 목적, 원문 근거, 화면 설명, 시각 자료 제안, 나레이션, 자막, 예상 시간 생성 |
| 검토 표시 | 근거 부족·사실 확인 필요 항목 표시 |
| 편집 | 장면별 모든 텍스트 필드 직접 수정 |
| 재생성 | 선택한 장면만 추가 지시와 함께 재생성 |
| 장면 관리 | 장면 추가, 삭제, 순서 변경 |
| 임시 저장 | 현재 브라우저에 자동 저장하고 새로고침 후 복구 |
| 결과 활용 | 전체 결과 복사, Markdown 및 CSV 내보내기 |
| 오류 처리 | 입력 오류, 네트워크 오류, AI 응답 오류 안내 및 재시도 |

### 4.2 후속 후보(P1)

- PDF·DOCX 파일 업로드 및 텍스트 추출
- 여러 참고자료 동시 입력
- 프로젝트 목록과 서버 저장
- 결과 버전 이력 및 이전 버전 복구
- 장면 템플릿과 조직별 작성 규칙
- DOCX·XLSX 내보내기
- 참고 이미지 검색 및 미리보기
- 팀원 댓글과 비실시간 공유 검토
- 한국어·영어 이외의 출력 언어

### 4.3 이번 MVP에서 제외하는 기능

- 실제 영상 자동 생성
- AI 음성 합성 및 음원 생성
- AI 이미지 생성
- 벡터 데이터베이스를 이용한 완전한 RAG
- 인터넷 자료 자동 검색 및 인용
- 여러 사용자의 실시간 공동편집
- 회원가입, 조직, 역할 및 권한 관리
- 결제 및 사용량 과금
- 모바일 애플리케이션
- 외부 영상 편집 도구와의 직접 연동

### 4.4 범위 결정 이유

첫 번째 MVP에서는 파일 파싱, 검색 인프라, 협업 기능보다 교육 콘텐츠 생성 결과와 사용자 검토 흐름이 실제로 유용한지를 먼저 확인한다. PDF·DOCX 처리와 완전한 RAG는 기본 흐름이 검증된 후 추가한다.

다만 장면별 `원문 근거`를 필수로 남겨 향후 RAG를 연결할 수 있는 데이터 구조는 유지한다.

## 5. 기본 사용자 흐름

1. 사용자가 새 작업을 시작한다.
2. 원고를 직접 입력하거나 TXT 파일을 불러온다.
3. 대상, 난이도, 영상 길이 등 생성 조건을 설정한다.
4. 사용자가 `스토리보드 생성`을 실행한다.
5. 시스템이 진행 상태를 표시하고 중복 생성을 막는다.
6. AI가 콘텐츠 개요와 장면별 초안을 반환한다.
7. 시스템이 필수 항목과 출력 형식을 검증한다.
8. 사용자가 전체 구조와 장면별 내용을 검토·수정한다.
9. 필요한 경우 특정 장면만 추가 지시와 함께 다시 생성한다.
10. 사용자가 장면을 추가·삭제·재정렬한다.
11. 검토가 끝난 결과를 복사하거나 파일로 내보낸다.

## 6. 입력 요구사항

### 6.1 원고 입력

| 항목 | MVP 규칙 |
|---|---|
| 입력 방식 | 텍스트 직접 입력·붙여넣기 또는 TXT 파일 불러오기 |
| 최소 길이 | 공백 제외 100자 |
| 최대 길이 | 공백 포함 20,000자 |
| 문자 수 표시 | 현재 글자 수와 최대 글자 수를 실시간 표시 |
| 빈 입력 처리 | 생성 버튼을 비활성화하고 입력 안내 표시 |
| 초과 입력 처리 | 초과한 글자 수를 표시하고 생성 요청 차단 |
| TXT 오류 | 읽을 수 없는 파일이면 원고 입력창을 유지한 채 오류 표시 |

### 6.2 생성 조건

| 항목 | 형식 | 필수 여부 | 기본값 |
|---|---|---:|---|
| 학습 대상 | 초등 저학년·초등 고학년·중고등학생·대학생/일반인·실무자/전문가 | 필수 | 대학생/일반인 |
| 설명 난이도 | 쉬움·보통·심화 | 필수 | 보통 |
| 목표 영상 길이 | 1~10분 | 필수 | 3분 |
| 장면 수 | 자동 또는 3~20개 | 필수 | 자동 |
| 톤앤매너 | 친근한 설명·차분한 교육·공식적·간결한 안내 | 필수 | 차분한 교육 |
| 강조 키워드 | 최대 10개 | 선택 | 없음 |
| 출력 언어 | 한국어·영어 | 필수 | 한국어 |
| 추가 요청 | 최대 500자 자유 입력 | 선택 | 없음 |

## 7. 출력 요구사항

### 7.1 콘텐츠 전체 정보

- 콘텐츠 제목
- 핵심 요약
- 학습 목표 1~5개
- 전체 예상 재생 시간
- 생성 조건 요약

### 7.2 장면별 필수 정보

| 필드 | 설명 |
|---|---|
| 장면 번호 | 현재 장면 순서 |
| 장면 제목 | 장면 내용을 짧게 나타내는 제목 |
| 장면 목적 | 해당 장면에서 학습자가 이해해야 할 한 가지 중심 내용 |
| 원문 근거 | 장면 생성에 사용된 원문의 인용 또는 식별 가능한 구간 |
| 화면 설명 | 실제 제작 화면에서 보여줄 대상과 동작 |
| 시각 자료 제안 | 사진, 도표, 애니메이션, 강조 텍스트 등 필요한 자료 |
| 나레이션 | 음성으로 읽을 수 있는 자연스러운 문장 |
| 자막 | 나레이션을 그대로 복사하지 않은 핵심 문장, 최대 두 문장 |
| 예상 시간 | 장면의 예상 재생 시간(초) |
| 검토 필요 | 사용자가 확인해야 하는지 여부 |
| 검토 사유 | 근거 부족, 수치 확인, 표현 검토 등 확인 이유 |

### 7.3 출력 품질 규칙

- 원문의 핵심 의미와 전개 순서를 유지한다.
- 원문에 없는 수치, 통계, 인물, 사례 또는 단정적 사실을 추가하지 않는다.
- 한 장면에는 하나의 중심 메시지만 배치한다.
- 전문용어는 학습 대상에게 필요한 경우 처음 등장할 때 설명한다.
- 화면 설명은 제작자가 무엇을 보여줘야 하는지 판단할 수 있도록 구체적으로 작성한다.
- 나레이션과 자막은 역할을 구분하고 동일한 문장을 반복하지 않는다.
- 장면별 예상 시간의 합은 목표 영상 길이의 ±15% 범위가 되도록 한다.
- 근거가 부족하면 임의로 채우지 않고 `검토 필요`와 사유를 표시한다.
- 지정된 출력 구조 이외의 설명문을 AI 응답에 추가하지 않는다.

## 8. 기능 요구사항

### FR-001 원고 입력

사용자는 원고를 직접 입력·붙여넣기 하거나 TXT 파일에서 불러올 수 있어야 한다.

완료 조건:

- 입력창에 문자 수가 실시간으로 표시된다.
- 입력 길이 조건을 충족하지 않으면 생성할 수 없다.
- TXT를 불러온 뒤 사용자가 내용을 직접 수정할 수 있다.
- 불러오기 실패 시 기존 입력 내용이 사라지지 않는다.

### FR-002 생성 조건 설정

사용자는 생성 전에 학습 대상, 난이도, 영상 길이, 장면 수, 톤앤매너, 강조 키워드, 출력 언어 및 추가 요청을 설정할 수 있어야 한다.

완료 조건:

- 필수값이 비어 있으면 생성 버튼이 비활성화된다.
- 현재 선택값을 생성 전에 확인할 수 있다.
- 동일한 원고에서 설정값을 변경해 다시 생성할 수 있다.

### FR-003 스토리보드 생성 요청

사용자는 유효한 원고와 설정값으로 전체 스토리보드 생성을 요청할 수 있어야 한다.

완료 조건:

- 생성 중 진행 상태가 표시된다.
- 생성 중 같은 요청을 중복 실행할 수 없다.
- 사용자가 입력한 원고와 설정값이 생성 요청에 포함된다.
- 생성 실패 후에도 입력 원고와 설정값이 보존된다.

### FR-004 콘텐츠 개요 생성

시스템은 콘텐츠 제목, 핵심 요약, 학습 목표 및 전체 예상 시간을 생성해야 한다.

완료 조건:

- 모든 필수 항목이 구분되어 표시된다.
- 사용자가 각 항목을 직접 수정할 수 있다.
- 수정 내용이 결과 내보내기에 반영된다.

### FR-005 장면별 초안 생성

시스템은 정해진 출력 구조에 따라 장면별 초안을 생성해야 한다.

완료 조건:

- 모든 장면에 장면 제목, 목적, 원문 근거, 화면 설명, 시각 자료 제안, 나레이션, 자막 및 예상 시간이 포함된다.
- 요청한 장면 수 또는 자동 결정된 장면 수가 화면에 표시된다.
- 장면 번호가 표시 순서와 일치한다.
- 필수 필드가 누락된 AI 응답은 정상 결과로 확정하지 않는다.

### FR-006 원문 근거와 검토 필요 표시

사용자는 각 장면이 원문의 어느 내용에서 생성됐는지 확인할 수 있어야 한다.

완료 조건:

- 모든 장면에 원문 근거가 표시된다.
- 근거가 부족한 장면은 `검토 필요` 상태로 구분된다.
- 검토 필요 상태에는 사유가 함께 표시된다.
- 색상만으로 검토 상태를 구분하지 않는다.

### FR-007 장면별 편집

사용자는 생성된 장면의 각 텍스트 필드를 직접 수정할 수 있어야 한다.

완료 조건:

- 편집 내용이 입력 즉시 화면 상태에 반영된다.
- 다른 장면을 편집해도 기존 수정 내용이 유지된다.
- 사용자가 수정한 필드와 AI 원본을 구분할 수 있다.
- 새로고침 후 현재 브라우저에서 수정 내용을 복구할 수 있다.

### FR-008 선택 장면 재생성

사용자는 전체 결과를 다시 만들지 않고 선택한 장면만 다시 생성할 수 있어야 한다.

완료 조건:

- 재생성 전에 최대 300자의 추가 지시를 입력할 수 있다.
- 재생성 대상 장면 외의 내용은 변경되지 않는다.
- 사용자가 수정한 다른 장면의 내용은 유지된다.
- 재생성 실패 시 기존 장면이 보존된다.
- 새 결과를 적용하기 전 기존 내용과 교체된다는 사실을 안내한다.

### FR-009 장면 관리

사용자는 장면을 추가·삭제하고 순서를 변경할 수 있어야 한다.

완료 조건:

- 새 장면을 원하는 위치에 추가할 수 있다.
- 삭제 전에 확인 절차가 제공된다.
- 순서 변경 후 장면 번호가 자동으로 갱신된다.
- 변경된 순서가 내보내기 결과에 반영된다.

### FR-010 자동 저장과 복구

시스템은 사용자의 현재 작업을 동일 브라우저에 자동 저장해야 한다.

완료 조건:

- 원고, 설정값, 생성 결과 및 사용자 수정 내용이 저장된다.
- 새로고침 후 마지막 작업을 복구할 수 있다.
- 사용자가 `새 작업`을 선택하면 기존 내용을 지울지 확인한다.
- 서버 데이터베이스에 사용자 원고를 영구 저장하지 않는다.

### FR-011 결과 복사와 내보내기

사용자는 현재 편집 상태의 결과를 복사하거나 파일로 내보낼 수 있어야 한다.

완료 조건:

- 전체 결과를 구조가 유지된 Markdown 형식으로 복사할 수 있다.
- 결과를 Markdown 파일과 CSV 파일로 내려받을 수 있다.
- 파일에는 사용자가 수정한 최신 내용과 현재 장면 순서가 반영된다.
- 내보내기 실패 시 화면의 편집 내용이 사라지지 않는다.

### FR-012 오류 처리와 재시도

시스템은 입력, 네트워크 및 AI 생성 오류를 사용자가 이해할 수 있는 문장으로 안내해야 한다.

완료 조건:

- 오류 원인과 사용자가 취할 다음 행동을 함께 표시한다.
- 네트워크 또는 서버 오류 발생 시 재시도 기능을 제공한다.
- AI 출력 구조가 잘못되면 자동으로 한 번 재시도한다.
- 일부 장면만 유효한 경우 유효한 결과를 보존하고 실패 장면을 표시한다.
- 오류 메시지에 API 키나 내부 시스템 정보를 노출하지 않는다.

## 10. 비기능 요구사항

### NFR-001 성능

- 공백 포함 10,000자 이하 원고와 자동 장면 수 기준으로 생성 요청의 80%를 90초 이내에 완료하는 것을 초기 목표로 한다.
- 사용자의 편집 입력은 눈에 띄는 지연 없이 화면에 반영돼야 한다.
- 생성 시간이 길어져도 진행 중임을 확인할 수 있어야 한다.

### NFR-002 안정성

- 생성 중 오류가 발생해도 원고와 설정값을 보존한다.
- 같은 생성 요청이 중복 전송되지 않도록 한다.
- 필수 출력 필드가 누락된 결과를 정상 결과로 저장하지 않는다.
- 브라우저 자동 저장 실패 시 사용자에게 알린다.

### NFR-003 보안과 개인정보

- AI API 키를 브라우저 코드에 포함하거나 사용자에게 노출하지 않는다.
- AI 요청은 서버 기능을 통해 전달한다.
- 원고와 생성 결과는 MVP 서버 데이터베이스에 영구 저장하지 않는다.
- 브라우저에 임시 저장된 작업을 사용자가 직접 삭제할 수 있어야 한다.
- AI 모델 제공자에게 전송되는 데이터 범위와 보관 정책은 실제 모델 선정 후 안내한다.

### NFR-004 사용성

- 사용자가 현재 단계와 다음 행동을 쉽게 확인할 수 있어야 한다.
- 오류 메시지는 문제 원인뿐 아니라 해결 방법도 안내해야 한다.
- 삭제·초기화처럼 복구가 어려운 작업은 실행 전에 확인한다.
- 장면 카드의 필수 항목 이름과 순서를 모든 장면에서 동일하게 유지한다.

### NFR-005 접근성

- 모든 입력 요소에 텍스트 레이블을 제공한다.
- 키보드만으로 주요 입력·생성·편집·내보내기 기능을 사용할 수 있어야 한다.
- 충분한 명암 대비를 사용한다.
- 오류와 검토 상태를 색상만으로 표현하지 않는다.

### NFR-006 호환성

- 최신 데스크톱 Chrome을 우선 지원한다.
- Edge와 Safari 최신 버전에서 핵심 흐름이 동작하는지 확인한다.
- 모바일 웹에서는 원고 입력, 결과 확인 및 기본 편집이 가능해야 하지만 별도 모바일 앱은 제공하지 않는다.

## 13. MVP 성공 지표

아래 수치는 첫 사용자 검증을 위한 초기 목표이며, 실제 테스트 결과에 따라 조정한다.

| 지표 | 초기 목표 |
|---|---|
| 전체 작업 완료율 | 테스트 사용자의 80% 이상이 도움 없이 입력부터 내보내기까지 완료 |
| 필수 출력 항목 충족률 | 정상 완료된 생성 결과의 100% |
| 원문 근거 표시율 | 전체 장면의 100% |
| 중대한 원문 왜곡 | 검토 표본에서 0건 |
| 대상·난이도 적합성 | 평가 평균 5점 만점 중 4점 이상 |
| 최초 초안 준비 시간 | 원고 입력 완료 후 10분 이내 |
| 수작업 대비 시간 단축 | 동일 과업 기준 30% 이상 |
| 편집 내용 보존 | 정상 사용 시 데이터 손실 0건 |

## 14. 데이터 처리 원칙

- MVP는 로그인과 서버 프로젝트 저장 기능을 제공하지 않는다.
- 원고, 설정값 및 편집 결과는 사용자의 현재 브라우저에 임시 저장한다.
- AI 생성을 위해 필요한 데이터만 서버 기능을 거쳐 모델 API에 전달한다.
- 서버는 생성 처리 후 원고와 결과를 영구 데이터베이스에 저장하지 않는다.
- 사용자는 현재 브라우저의 임시 작업을 삭제할 수 있다.
- 내보낸 파일의 보관과 공유는 사용자가 관리한다.

## 15. 향후 RAG 연결을 위한 준비

MVP에서는 벡터 검색을 구현하지 않지만 다음 항목은 처음부터 유지한다.

- 각 장면의 원문 근거 텍스트
- 원문 내 근거 위치를 연결할 수 있는 식별자
- 검토 필요 여부와 사유
- 사용자가 수정한 결과와 AI 생성 결과의 구분
- 향후 참고자료 출처를 추가할 수 있는 확장 가능한 장면 구조

이를 통해 후속 단계에서 문서 분할, 임베딩, 검색, 출처 표시 및 근거 평가 기능을 추가할 수 있게 한다.

## 16. 출시 판단 기준

다음 조건을 모두 충족하면 첫 번째 MVP를 팀 내부 테스트에 사용할 수 있는 상태로 판단한다.

1. P0 기능이 구현되고 관련 인수 조건을 통과한다.
2. 최소 5개의 서로 다른 교육 원고로 전체 흐름 테스트를 완료한다.
3. 테스트 결과에서 중대한 원문 왜곡이 발견되지 않는다.
4. 생성 실패와 네트워크 오류가 발생해도 사용자의 입력과 기존 결과가 보존된다.
5. Markdown 및 CSV 내보내기 결과를 실제 제작자가 읽고 사용할 수 있다.
6. API 키가 클라이언트에 노출되지 않는다.
