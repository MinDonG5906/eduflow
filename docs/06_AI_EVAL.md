# EduFlow AI 생성 품질 평가표

작성일: 2026-10-27  
근거: [진행 현황 및 다음 방향](TEAM_STATUS_DIRECTION_2026-09-29.md) 5장 "AI 평가 기준"·"품질과 안정성 검증"

같은 원고를 누가 평가해도 비슷한 점수가 나오도록 채점 기준과 진행 절차를 고정한다. 형식·길이는 `npm run eval`이 자동으로 검사하고, 의미와 품질은 사람이 이 표로 채점한다.

## 1. 공식 통과 기준

팀 문서에서 정한 세 가지다. 셋 다 충족해야 통과다.

| 기준 | 판정 방법 |
| --- | --- |
| 중대한 원문 왜곡 0건 | 두 평가자가 합의한 "중대 왜곡 건수"의 5건 합계가 0 |
| 필수 항목 충족 100% | 자동 검사의 "형식·필수 항목"과 "장면 수"가 5건 모두 통과. 생성 실패는 미충족 |
| 대상·난이도 적합성 평균 4/5 이상 | 3번 항목의 합의 점수 5건 평균이 4.0 이상 |

**권장 기준**(팀 합의 전 참고값): 1·2·4~8번 항목 평균 3.5 이상, 9번 체크리스트 모두 통과.

## 2. 중대한 원문 왜곡

아래 중 하나라도 해당하면 1건으로 센다. 같은 오류가 여러 장면에 반복되면 장면마다 센다.

- 원문과 반대되는 지시: 금지와 허용, 해야 할 일과 하지 말아야 할 일이 뒤바뀜
- 원문에 없는 수치·절차·규정·사례를 사실처럼 추가
- 안전·법규상 꼭 필요한 단계나 조건을 빠뜨려 따라 하면 위험하거나 틀리게 됨
- 대상·주체를 바꿈. 예: 관리자 의무를 근로자 의무로 설명

## 3. 사람 평가 항목

1~5점으로 채점한다. 아래 표는 5·3·1점 기준이며, 2점과 4점은 그 사이일 때 준다. "전체" 항목은 스토리보드 하나에 한 번, "장면" 항목은 장면마다 채점한다.

| 항목 | 단위 | 5점 | 3점 | 1점 |
| --- | --- | --- | --- | --- |
| 1. 핵심 내용 누락·왜곡 | 전체 | 원문의 핵심 내용이 모두 있고 의미가 같다 | 부수적인 내용이 1~2개 빠졌거나 과장·축소가 있지만 교육 의도는 유지된다 | 핵심 내용이 빠졌거나 중대한 왜곡이 1건 이상 있다 |
| 2. 장면 구분·교육 흐름 | 전체 | 장면마다 중심 메시지가 하나이고, 원문 순서를 따라 도입→설명→정리로 이어진다 | 일부 장면에 메시지가 두 개 이상이거나 순서가 한두 곳 어색하다 | 장면 구분이 임의적이거나 순서가 뒤섞여 이해하기 어렵다 |
| 3. 대상·난이도 적합성 | 전체 | 선택한 교육대상과 난이도에 맞는 어휘·예시·문장 길이다 | 대체로 맞지만 어려운 용어나 긴 문장이 여러 곳 있다 | 대상과 맞지 않는다. 예: 전문용어 남발, 외국인 근로자에게 복잡한 문장 |
| 4. 화면 설명 제작 가능성 | 장면 | 디자인·촬영 담당자가 추가 질문 없이 만들 수 있을 만큼 구체적이다 | 무엇을 보여줄지는 알지만 구도나 자료를 따로 정해야 한다 | 추상적이어서 무엇을 만들지 알 수 없다 |
| 5. 나레이션 자연스러움 | 장면 | 소리 내어 읽으면 자연스럽고 장면 시간 안에 읽힌다 | 어색한 표현이나 번역투가 있거나 시간이 빠듯하다 | 읽기 어렵거나 장면 시간 안에 읽을 수 없다 |
| 6. 자막 길이·가독성·의미 일치 | 장면 | 한 화면에서 읽을 수 있는 길이(40자 이하 권장)이고 나레이션의 핵심과 같다 | 길거나 나레이션과 일부 다르다 | 너무 길어 읽을 수 없거나 나레이션과 의미가 다르다 |
| 7. 원문 근거 정확성 | 장면 | 근거 인용이 원문에 그대로 있고 장면 내용을 실제로 뒷받침한다 | 원문에는 있지만 장면 내용과 일부만 관련된다 | 근거가 비었거나 원문에 없는 내용이다 |
| 8. 목표 시간 적합성 | 전체 | 합계가 목표의 ±10% 이내이고 장면별 시간이 내용 분량에 맞다 | 합계는 맞지만 배분이 어색하거나 합계가 ±10~20% 벗어난다 | 합계가 ±20%를 넘거나 장면 시간에 내용을 담을 수 없다 |

### 9. 실패 시 보존 (평가 회차마다 한 번)

화면에서 직접 확인하는 체크리스트다. 모두 통과하면 5점, 하나 실패하면 3점, 둘 이상 실패하면 1점이다.

- [ ] 전체 생성 중 취소해도 원고·설정·기존 결과가 그대로 있다
- [ ] 생성이 실패하거나 시간이 초과되어도 원고·설정·기존 결과가 그대로 있고, 다시 시도할 수 있다
- [ ] 선택 장면 재생성이 실패해도 다른 장면과 직접 수정한 내용이 그대로 있다
- [ ] 새로고침 후 원고·설정·결과가 복구된다

## 4. 자동 검사

`npm run eval`이 케이스마다 아래 항목을 검사한다. 검사 코드는 `lib/eval-checks.ts`에 있다.

| 검사 | 기준 | 결과 |
| --- | --- | --- |
| 형식·필수 항목 | 생성 응답 계약([03_AI_SPEC](03_AI_SPEC.md))의 필수 항목과 길이 | 실패 시 필수 항목 미충족 |
| 장면 수 | 요청한 장면 수(자동이면 `분 × 2`, 3~12개)와 같음 | 실패 시 필수 항목 미충족 |
| 목표 시간 | 장면 시간 합계가 `목표(분) × 60초`의 ±10% 이내 | 경고 |
| 원문 근거 | 서버 근거 경고 + 근거 인용이 원문에 그대로 있는지 다시 확인 | 경고 |
| 자막 길이 | 공백을 하나로 줄여 40자 이하 | 경고 |
| 나레이션 속도 | 공백 제외 초당 3~8자 (한국어 출력만) | 참고 |
| 용어 교정 | 서버의 자동 용어 교정 내역 | 참고 |

경고와 참고는 통과·실패를 정하지 않는다. 채점할 때 해당 장면을 먼저 확인하라는 표시다.

## 5. 진행 절차

1. **원고 준비**: `eval/manuscripts/`에 실제 교육 원고 5건을 UTF-8 텍스트로 넣는다. 첫 줄은 제목이다. `eval/cases.json`의 원고 경로와 설정을 고치고 `placeholder`를 `false`로 바꾼다. 교육대상·난이도·길이를 케이스마다 다르게 정한다. 실제 모델 평가 시 원고가 OpenAI로 전송되므로 개인정보·비공개 정보가 없는지 확인한다.
2. **무료 사전 검사**: `npm run eval`. 데모로 케이스 파일과 원고 형식을 확인한다. 데모는 원문을 나누기만 하므로 품질 판정에 쓰지 않는다.
3. **실제 모델 생성**: 서버를 실제 AI 모드로 실행한 뒤 아래 명령을 실행한다.
   ```sh
   npm run eval -- --server http://127.0.0.1:3000 --confirm-paid
   ```
   서버의 `/api/generate`를 호출하므로 키 관리와 팀 비용 상한(하루 1달러·월 5달러, Gemini 팀 키는 별도 한도)이 그대로 적용된다. 1회 상한이 0.10달러이면 5건에 최대 약 0.5달러다. 비용 한도에 도달하면 남은 케이스는 호출하지 않고 건너뛴다. `.env.example`의 시간당 호출 5회 제한도 그대로 적용되므로, 5건을 한 번에 실행하면 그 시간 안에는 다시 실행할 수 없다. `--only <케이스 id>`로 한 건만 다시 실행할 수 있다.
4. **채점**: 결과 폴더 `eval/results/<실행 시각>/`의 `scoring.csv`를 평가자마다 `scoring-<이름>.csv`로 복사한다. 두 평가자가 서로의 점수를 보지 않고 채점한다. "전체" 행에는 1·2·3·8번과 중대 왜곡 건수를, 장면 행에는 4~7번을 적는다. "해당 없음" 칸은 비워 둔다.
5. **합의**: 같은 칸의 점수가 2점 이상 차이 나면 원고를 함께 보고 합의 점수를 정한다. 1점 차이는 평균을 쓴다. 중대 왜곡은 합의한 건수만 센다.
6. **판정과 기록**: 1장의 공식 기준 세 가지를 판정한다. `summary.md`와 합의 점수를 팀 공유 위치에 보관한다. `eval/results/`에는 원고와 생성 결과가 들어 있으므로 Git에 올리지 않는다.

## 6. 결과 파일

| 파일 | 내용 |
| --- | --- |
| `results.json` | 케이스별 설정, 생성 결과 전체, 자동 검사 결과, 응답 시간 |
| `summary.md` | 실행 방식·모델, 케이스별 자동 검사 요약, 확인할 장면 |
| `scoring.csv` | 사람 채점용 빈 시트 (UTF-8 BOM, Excel에서 바로 열림) |

## 7. 한계

- 현재 `eval/manuscripts/`의 원고 5건은 기존 자동 테스트 문장을 옮긴 **임시 표본**이다. 같은 문장이 반복되므로 이 원고로는 품질을 판정할 수 없다.
- 자동 검사는 형식·길이·인용 일치만 본다. 의미의 정확성, 교육 효과, 번역 품질은 사람이 판정한다.
- 나레이션 속도 3~8자/초와 자막 40자는 참고치다. 실제 녹음·편집 결과로 팀이 조정한다.
- PDF·PPT·한글 선택본 생성은 아직 케이스에 없다. 근거는 원본 페이지와 직접 대조해야 한다.
- 평가 스크립트는 모델 연결 방식과 관계없이 `/api/generate` 경계만 사용하므로 모델이나 로그인 방식이 바뀌어도 그대로 쓸 수 있다.
